
## Overview

AXcellent는 업무별 AI 에이전트를 배치하고, 요청 접수부터 분석·기획·개발·마케팅까지 에이전트들이 서로 업무를 전달하며 처리하는 업무 자동화 솔루션입니다. 사람은 최종 결정과 승인만 담당하며, 비용이 발생하거나 외부에 콘텐츠를 게시하는 작업은 반드시 승인 절차를 거쳐야 실행됩니다.

팀원들과 함께 개발한 개인 팀 프로젝트로, 총 5개의 저장소로 구성되어 있습니다. AI 에이전트들이 업무를 수행하는 **AXcellent 본체**, 서버 장애를 담당하는 **DejaFix(인프라 AI)**, 그리고 AI가 실제 업무를 수행할 수 있도록 구성한 **가상 고객사 3곳(캣북스·스터디온에듀·누비투어)**입니다.

저는 **AI Agent Developer**로 참여했고, 담당 영역은 다음과 같습니다.

- **재무 AI**: 처음부터 설계하고 개발했습니다.
- **마케팅 AI**: 콘텐츠 제작과 Higgsfield·유튜브·인스타그램 연동을 맡았습니다.
- **인프라 AI (DejaFix)**: Zabbix 개발 환경 구축, 장애 주입, 과거 장애 RAG 지식 검색을 맡았습니다.
- **안전 처리 로그 (안전 규칙)**: 비용이 들거나 외부에 게시하는 작업을 승인 관문에 등록하고, 판정 기록과 사람 결정 대기 화면을 만들었습니다.
- **그 외**: 협업 루프와 CI 구성, 운영 배포, 성능 개선을 진행했습니다.

### 에이전트 간 통신은 A2A로 통일

- 각 에이전트는 독립적인 업무 로직을 가지고 있으며, 다른 에이전트의 내부 로직을 직접 가져다 쓰지 않고 A2A 호출을 통해서만 업무를 요청합니다. 특정 에이전트를 수정하더라도 다른 에이전트에 미치는 영향을 최소화하기 위한 구조입니다.
- 예를 들어 데이터분석 AI가 발견한 트렌드를 기획 AI에 전달하고, 마케팅 AI는 캠페인을 시작하기 전에 재무 AI에 예산 검토를 요청합니다.
- 에이전트 간 입출력 형식인 계약(Contract)은 한곳에서 관리하며, 기존 항목을 삭제하거나 이름·타입을 변경하지 않고 확장하는 방식으로 유지합니다.

### 상태 변경은 승인 관문을 통해서만 실행

- 에이전트가 시스템 상태를 변경하는 모든 작업은 공용 실행 함수를 거쳐 안전 규칙의 등급(A·B·C)에 따라 판정받습니다.
- 환불과 쿠폰 발급은 금액이 기준을 초과하면 승인이 필요하며, 판매자 정산 지급과 SNS 게시 작업은 항상 사람의 승인을 거쳐야 실행됩니다. 모든 판정 결과는 안전 처리 로그에 기록됩니다.
- DejaFix(인프라 AI)에도 동일한 원칙을 적용했습니다. 실행 가능 여부는 규칙 파일과 코드가 결정하며 LLM은 실행 여부를 판단하지 않습니다. Zabbix 역시 읽기 전용으로만 조회합니다.

### 고객사 데이터는 API로 연동하고, 여러 회사는 하나의 서버로 관리

- 고객사 시스템의 화면을 그대로 가져오는 대신, 고객사가 제공하는 API를 통해 데이터만 받아 AXcellent에서 직접 화면을 구성합니다. 데이터 쓰기는 환불, 쿠폰 발급, 공지 게시 등 안전 관문을 통과한 작업만 허용합니다.
- 인프라 AI도 동일한 구조입니다. AXcellent의 장애 대응 탭은 DejaFix(인프라 AI) API에서 현재 발생한 장애 데이터를 받아 화면에 표시합니다.
- 회사별 연결 정보·키·설정을 각각 관리하고, 화면은 로그인한 회사 기준으로, 에이전트는 요청에 포함된 회사 기준으로 데이터를 읽고 씁니다. 이를 통해 업종이 서로 다른 세 고객사를 하나의 AI 아키텍처로 관리할 수 있습니다.

### 시연 시나리오: 퇴근한 밤, 결제가 멈추면

1. **감지**: 인프라 AI가 쇼핑몰의 결제 오류 신호를 감지하고, 총괄 AI가 이슈를 생성해 업무를 분배합니다.
2. **분석**: 과거의 유사 장애와 대응 사례를 검색하고, 데이터분석 AI가 결제 실패 주문 수와 영향받은 고객, 피해 금액을 집계합니다.
3. **조치**: 과거 대응 방식을 참고해 장애를 해결하고, 마케팅 AI는 장애 공지를 작성하며 고객지원 AI는 피해 고객에 대한 보상 방안을 마련합니다.
4. **기록**: 재무 AI가 보상 금액을 장부에 기록하고, 이번 장애 사례를 다음 장애 발생 시 다시 활용할 수 있도록 저장합니다.

가상 데이터로 구성한 시연 환경에서 장애 감지부터 기록까지 총 36초가 걸렸으며, AI 에이전트 간 요청은 총 17건이 발생했습니다.

### 작업 방식

- 기본 브랜치에 직접 커밋하지 않고, PR과 CI 검증을 통과한 변경 사항만 머지합니다.
- 팀원들은 각자 Claude Code를 활용해 개발하며, 사전에 정의한 이슈는 Claude Code 루프가 가져와 처리하는 방식으로 진행합니다.

## Work

### 재무 AI (AXcellent)

- 결산, 판매자 정산, 은행 입금 대조, 13주 현금 흐름 예측, 월 마감 체크리스트 기능을 개발했습니다.
- 은행 거래내역과 PG 정산 파일을 화면에서 업로드하면 재무 AI가 데이터를 읽고 대조합니다. 일치하지 않는 항목은 예외 건으로 분류합니다.
- 부가세 신고 보조 집계, 분기 재무제표 확정, 월 조정 분개 기능을 구현했습니다. 확정된 결산 수치는 고정하고, 이후 변경 사항은 차이로 표시하도록 했습니다.
- 일정 금액을 초과하는 정산 지급과 본인 승인 작업을 차단했습니다. 사람의 확인이 필요한 항목은 '지금 사람이 할 일'에 표시해 바로 검토하고 결정할 수 있도록 했습니다.
- 재무제표 엑셀 다운로드와 전문가 확인 목록 Word 파일 생성 기능을 추가했습니다.
- 계산 정확도를 검증하는 평가 시스템을 구축했습니다. 무작위로 생성한 장부 1,000개를 정책에 따라 별도로 계산한 정답과 비교하고, 실제 서버와 동일한 데이터 조회 경로를 사용하는 holdout 평가도 수행합니다.

### 재무 AI와 다른 AI의 협업

- 마케팅 캠페인에 대한 승인·반려 권한은 부여하지 않고, 의견만 제시하도록 역할을 분리했습니다. 콘텐츠 카테고리별 조회당 제작비를 분석해 예산 재배분 의견을 기획 AI에 전달합니다.
- 기획 AI가 영상 기획안을 전달하기 전에 재무 AI에 예상 제작비를 문의하고, 재무 AI는 전달받은 근거를 바탕으로 관련 질문에 답변합니다.
- 고객지원 AI가 집계한 클레임 데이터를 참고해 문제가 많은 상품의 광고 예산에 대한 의견을 제시하고, 인사 AI가 관리하는 팀 인원 정보를 활용해 팀 예산을 계산합니다.
- 장애가 발생하면 총괄 AI가 재무 AI에 장부 기록을 요청하고, 재무 화면에서는 총괄 AI가 전달한 장애 진단 내용도 함께 확인할 수 있도록 했습니다.
- 과거에 동일한 장애가 발생한 이력이 있다면 총괄 AI가 당시의 대응 방식을 다시 활용해 빠르게 문제를 해결하도록 구성했습니다.

### DejaFix(인프라 AI)

- 로컬 개발 환경에서 Zabbix 7.0 서버를 Docker Compose로 실행할 수 있도록 환경을 구성했습니다. 초기 설정 스크립트와 점검·진단 도구, 핵심 지표 대시보드 시제품도 함께 개발했습니다.
- 시연용 장애를 재현하기 위한 CPU 부하 주입·정리 스크립트와 데모 트리거 템플릿을 만들었습니다. 트리거가 실제로 발생하기까지 걸리는 시간인 104초를 측정하고 이를 바탕으로 시연 목표를 조정했습니다.
- AI가 Zabbix를 조회할 때 사용하는 MCP 도구 계약을 정의했습니다. 필수 도구 5개와 공통 응답 형식을 확정하고, CPU·메모리·디스크·네트워크 등 IT 핵심 지표 키를 정리했습니다.
- **RAG 기반 장애 대응 지식 도우미**를 담당했습니다. 지식 검색 MCP 서버(`kb_search_knowledge`), 임베딩 처리(429 응답 재시도 포함), 전체·부분 재색인 기능을 구현하고 장애 분석과 채팅에 유사한 과거 사례 및 런북을 연결했습니다.
- 수집되지 않은 정보에 대한 질문에는 임의로 내용을 생성하지 않고, 근거가 없다는 사실을 명확히 밝히도록 채팅 응답을 개선했습니다.
- 데모 리허설을 진행해 장애 주입부터 담당자 이메일 발송까지 총 2분 59초를 기록했으며, 데모 대체 경로를 정리한 문서도 작성했습니다.

### 마케팅 AI

- **Higgsfield 연동**: 회사마다 자기 Higgsfield 계정을 원격 MCP(OAuth)로 연결하고, 구독 크레딧으로 이미지와 영상을 만듭니다. 남은 크레딧과 프로필 링크도 화면에서 확인할 수 있습니다.
- **콘텐츠 제작 흐름**: 캐릭터 이미지와 줄거리를 넣으면 캐릭터 시트 → 영상 대본 → 스토리보드 → 영상 순서로 제작 기록이 이어집니다. 이미지 시트와 스토리보드는 Higgsfield로 실제 그림을 만들고, 모션 참조 영상을 올리면 그 동작을 따라 영상을 만듭니다.
- **썸네일과 BGM**: 영상 썸네일 후보 3장을 만들어 사람이 고르게 하고, 영상에 입힐 BGM도 생성합니다.
- **유튜브 연동**: 회사마다 구글 OAuth로 유튜브 채널을 연결하고, 제작 기록이나 대화방 의뢰로 만든 영상을 AI가 쓴 제목·설명과 함께 올립니다. 올린 영상의 성과는 데이터 AI를 거쳐 기획 결과에 담깁니다.
- **인스타그램 연동**: 회사마다 인스타그램 로그인을 연결하고, 영상을 고른 썸네일을 표지로 해 릴스로 올립니다.
- 대화방 의뢰 카드에서 유튜브·인스타그램에 바로 올릴 수 있고, 모든 게시는 사람 승인 뒤에만 실행됩니다.
- 유튜브 영상을 캠페인에 연결해 재무 AI의 조회당 제작비 계산에 싣고, 캠페인별 광고 숫자 기록과 추적 링크를 만들었습니다.
- 공지 문안은 LLM이 쓰되 코드 검증을 통과할 때만 쓰고, 공지·쿠폰 기록은 DB에 남기며 보내지 못한 이벤트는 outbox로 다시 보냅니다.

### 안전 처리 로그 (안전 규칙)

- 안전 규칙 AI의 메뉴와 화면, 1:1 대화, AI 오피스 자리를 만들고, AI 대화방에서 안전 규칙 AI에게 직접 말을 걸 수 있게 했습니다.
- 최근 판정 기록을 날짜별로 고를 수 있게 하고, 관문 밖에서 사람 확인을 기다리는 일(기록·중복 결정·발령)까지 "사람 결정 대기"에 모았습니다.
- SNS 게시, 이미지·영상 생성, BGM 생성, 마케팅 대화를 관문에 등록하고 예상 사용량에 맞춰 비용 기준을 정했습니다.
- 외부 연결 쓰기에 연결 정보가 빠지거나 취약한 연결이면 사람 보류로 보내고, 보유기간이 지난 개인정보를 한꺼번에 지우는 일도 사람이 확인하게 했습니다.
- 재시작해도 보류 큐와 실행 기록이 남고, 결정에는 승인자 이름이 남도록 했습니다.

### 캣북스

- 목(Mock) 모드 없이 실제 모드에서 캣북스 판매 서버의 데이터를 A2A로 조회하도록 연동했습니다.
- 결제 응답이 시간 초과된 주문은 결제사에 다시 확인해 미결제 주문과 환불이 필요한 주문을 구분하도록 판매 서버 로직을 개선했습니다.
- 가상 주문 생성기가 결제 완료 주문을 발송 및 배송 완료 상태까지 이어서 기록하도록 구현했습니다.

### 스터디온에듀·누비투어

- 두 고객사 사이트는 팀원이 만들었고, 저는 AXcellent가 여러 고객사를 함께 받을 수 있는 기반을 맡았습니다.
- 요청마다 서버가 회사를 정하는 공용 회사 범위(Company Scope)와, 기존 데이터를 회사별 공간으로 옮기는 명령(retenant)을 만들었습니다.
- 재무 기록을 요청한 회사마다 따로 쌓도록 바꿔, 업종이 다른 고객사의 장부가 섞이지 않게 했습니다.
- 고객사 계정을 시스템 관리자 하나로 정리해, 한 계정에서 고객사를 바꿔 가며 볼 수 있게 했습니다.

### 협업 환경과 배포

- 팀이 함께 쓰는 Claude Code 협업 루프와 로컬 가드 훅, CLAUDE.md 규칙, CI를 처음 구성했습니다.
- 운영 서버 배포를 맡아 진행했습니다.

### 성능 개선

- 재무 화면에 페이지별 코드 분할(Code Splitting), 스켈레톤 화면, 중복 요청 방지, 장애 목록의 N+1 쿼리 제거를 적용해 성능을 개선했습니다.
- 동일한 장부 데이터를 기반으로 생성한 응답을 캐싱하고, 대화방을 열 때 재무 AI의 답변을 미리 생성하도록 구성했습니다.
- Lighthouse 기준 성능 점수는 66 → 94, 접근성은 97 → 100, SEO는 92 → 100으로 개선했습니다. 첫 콘텐츠 표시(FCP)는 2.7초에서 0.8초로, 최대 콘텐츠 표시(LCP)는 3.4초에서 1.6초로 단축했습니다.
