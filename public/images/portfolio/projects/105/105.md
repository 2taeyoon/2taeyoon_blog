## Overview

AXcellent는 부서마다 AI 에이전트를 두고, 요청 접수부터 분석·기획·개발·마케팅까지 에이전트끼리 일을 넘겨 처리하는 업무 자동화 솔루션입니다. 사람은 결정과 승인만 하고, 돈이 나가거나 외부에 게시하는 일은 승인 관문을 거쳐야 실행됩니다.

팀원들과 함께 만든 팀 프로젝트이고, 저장소 5개로 이뤄져 있습니다. 부서 AI가 일하는 **AXcellent 본체**, 서버 장애를 맡는 **인프라 AI(DejaFix)**, 그리고 AI가 실제로 일을 해 볼 **가상 고객사 3곳(캣북스·스터디온에듀·누비투어)** 입니다.

저는 **재무 AI**를 처음부터 맡아 만들었고, DejaFix에서는 **Zabbix 개발 환경과 장애 주입, RAG 지식 검색**을 맡았습니다. 그 밖에 프론트 화면, 마케팅 AI의 콘텐츠 제작, 안전 규칙 화면, 성능 개선 작업을 함께 했습니다.

## Architecture

### 저장소 5개의 역할

| 저장소 | 역할 | 기술 |
|---|---|---|
| AXcellent | 부서 AI 8개(총괄·고객지원·재무·데이터분석·인사·마케팅·기획·개발)와 안전 규칙, 업무 화면 | React 19, Vite, Tailwind / Python, FastAPI, a2a-sdk |
| DejaFix (인프라 AI) | Zabbix 알람을 받아 원인 후보와 영향 범위를 정리하고, 조치는 규칙으로 안전성을 판정한 계획으로만 제시 | React, Vite / FastAPI, MCP, SQLite, Docker Compose |
| 캣북스 | 책과 문구를 파는 가상 온라인 서점. 판매 서버와 쇼핑몰 화면, 결제 장애 스위치, 가상 주문 생성기 | FastAPI, React, Vite, nginx |
| 스터디온에듀 | 가상 온라인 강의 플랫폼. 수강생·강사·직원 화면과 외부 시스템용 API | Next.js, Prisma, PostgreSQL |
| 누비투어 | 가상 패키지여행 예약 사이트. 예약·결제·취소와 직원 관리 화면, 외부 시스템용 API | Next.js, Prisma, PostgreSQL |

### 에이전트끼리는 A2A로만

- 부서 업무 로직은 서로 직접 가져다 쓰지 않고, A2A 호출로만 일을 부탁합니다. 한 부서를 고쳐도 다른 부서가 함께 흔들리지 않게 하기 위해서입니다.
- 예를 들어 데이터분석 AI가 뜨는 주제를 기획 AI에 넘기고, 마케팅 AI는 캠페인을 시작하기 전에 재무 AI에 예산 검토를 부탁합니다.
- 에이전트 사이의 입출력 모양(계약)은 한곳에만 두고, 지우거나 이름·타입을 바꾸지 않고 추가만 합니다.

### 상태 변경은 승인 관문으로만

- 에이전트가 무언가를 바꾸는 일은 모두 공용 실행 함수를 거쳐 안전 규칙의 등급(A·B·C) 판단을 받습니다.
- 환불·쿠폰은 금액이 기준을 넘으면, 판매자 정산 지급과 SNS 게시는 항상 사람이 승인해야 실행됩니다. 모든 판단은 안전 처리 로그에 남습니다.
- DejaFix도 같은 원칙입니다. 실행 여부는 규칙 파일과 코드가 결정하고 LLM은 결정하지 않으며, Zabbix는 읽기 전용으로만 조회합니다.

### 고객사 데이터는 받기만, 여러 회사는 서버 하나로

- 고객사 시스템의 화면을 가져오지 않고, 고객사가 열어 준 API로 데이터만 받아 AXcellent가 직접 그립니다. 쓰기는 안전 관문을 거친 일(환불, 쿠폰 발급, 공지 게시 등)만 보냅니다.
- 인프라 AI도 마찬가지로, AXcellent의 장애 대응 탭은 DejaFix API에서 현재 장애만 받아 그립니다.
- 회사마다 연결 정보·키·설정을 한 줄씩 두고, 화면은 로그인한 회사, 에이전트는 요청에 담긴 회사 기준으로 데이터를 읽고 씁니다. 업종이 다른 세 고객사를 같은 AI 구조로 받는 이유입니다.

### 시연 시나리오: 퇴근한 밤 결제가 멈추면

1. **감지**: 인프라 AI가 쇼핑몰의 결제 오류 신호를 알아채고, 총괄 AI가 이슈를 열어 일을 나눕니다.
2. **분석**: 비슷한 과거 장애와 대응을 찾고, 데이터분석 AI가 실패 주문과 영향 고객, 피해 금액을 셉니다.
3. **조치**: 지난 대응법으로 장애를 풀고, 마케팅 AI가 장애 공지를, 고객지원 AI가 피해 고객 보상을 정합니다.
4. **기록**: 재무 AI가 보상 금액을 장부에 적고, 이번 이슈는 다음 장애 때 다시 찾아 쓸 수 있게 저장합니다.

시연 환경(가상 데이터)에서 감지부터 기록까지 36초, AI끼리 주고받은 요청은 17건이었습니다.

### 작업 방식

- 기본 브랜치에 직접 올리지 않고 PR과 CI 통과로만 머지합니다.
- 팀원 각자 Claude Code로 개발하고, 정해 둔 이슈는 Claude Code 루프가 받아 처리합니다.

## Work

### 재무 AI (AXcellent)

- 결산, 판매자 정산, 은행 입금 대조, 13주 현금 흐름, 월 마감 체크리스트를 만들었습니다.
- 은행 거래내역·PG 정산 파일을 화면에서 그대로 올리면 재무 AI가 읽어 대조하고, 맞지 않는 건은 예외로 올립니다.
- 부가세 신고 보조 집계, 분기 재무제표 확정, 월 조정 분개를 만들고, 확정한 결산 숫자는 고정해 이후 변동은 차이로 보여 줍니다.
- 큰 정산 지급과 자기 승인은 막고, 사람이 확인해야 하는 건은 "지금 사람이 할 일"에 올려 바로 결정할 수 있게 했습니다.
- 재무제표 엑셀 내려받기, 전문가 확인 목록 Word 파일 만들기를 붙였습니다.
- 계산 정확도 평가를 만들었습니다. 무작위로 만든 장부 1,000개를 정책대로 따로 계산한 정답과 비교하고, 실제 서버와 같은 읽기 경로로 holdout 평가도 돌립니다.

### 재무 AI와 다른 부서의 협업

- 마케팅 캠페인을 승인·반려하지 않고 의견만 내도록 역할을 나눴습니다. 콘텐츠 카테고리별 조회당 제작비를 보고 예산 재배분 의견을 기획 AI에 보냅니다.
- 기획 AI가 영상 기획안을 넘기기 전에 재무에 제작비를 묻고, 재무는 보낸 근거로 되묻기에 답합니다.
- 고객지원의 클레임 집계를 읽어 문제가 많은 상품의 광고 예산 의견을 줄이고, 인사의 팀 인원으로 팀 예산을 계산합니다.
- 장애가 나면 총괄 AI가 재무에 장부 기록을 맡기고, 재무 화면에서 총괄이 보낸 진단을 함께 봅니다.
- 같은 장애가 과거에 있었으면 총괄 AI가 그때의 처리 방식을 바로 다시 써서 빨리 풀도록 했습니다.

### 인프라 AI (DejaFix)

- 로컬 개발용 Zabbix 7.0 서버를 Docker Compose로 띄우는 환경과 초기 설정 스크립트, 점검·진단 도구, 핵심 지표 대시보드 시제품을 만들었습니다.
- 시연용 장애를 만드는 CPU 부하 주입·정리 스크립트와 데모 트리거 템플릿을 만들고, 트리거가 실제로 뜨기까지 걸리는 시간(104초)을 재서 목표를 다시 정했습니다.
- AI가 Zabbix를 조회할 때 쓰는 MCP 도구 계약(필수 5개 도구, 공통 응답 형식)과 IT 지표 키(CPU·메모리·디스크·네트워크)를 확정했습니다.
- **RAG 장애 대응 지식 도우미**를 맡았습니다. 지식 검색 MCP 서버(`kb_search_knowledge`), 임베딩(429 응답 재시도 포함), 전체·부분 재색인을 만들고, 장애 분석과 채팅에 비슷한 과거 사례와 런북을 붙였습니다.
- 수집하지 않는 질문에는 지어내지 않고 근거가 없다고 문장으로 밝히도록 채팅 답변을 다듬었습니다.
- 데모 리허설을 돌려 장애 주입부터 담당자 메일까지 2분 59초를 기록하고, 데모 대체 경로 문서를 남겼습니다.

### 가상 고객사 (캣북스)

- 목 모드 없이 실제 모드로 캣북스 판매 서버 데이터를 A2A로 읽어 오게 했습니다.
- 결제 응답이 시간 초과된 주문은 결제사에 다시 확인해 미결제와 환불 필요를 나누도록 판매 서버를 고쳤습니다.
- 가상 주문 생성기가 결제된 주문을 발송·도착 상태로 이어 적도록 했습니다.

### 마케팅 AI 콘텐츠 제작

- 회사 Higgsfield 계정과 MCP로 그림·영상을 만드는 흐름을 붙였습니다.
- 캐릭터와 줄거리를 넣으면 이미지 시트 → 영상 대본 → 스토리보드 순서로 제작 기록이 이어지게 했습니다.
- SNS 계정 연결을 하나로 합치고, 대화방 의뢰 카드에서 유튜브·인스타그램에 바로 올릴 수 있게 했습니다. 게시는 사람 승인 뒤에만 실행됩니다.
- 캠페인별 광고 숫자 기록과 추적 링크, 공지 문안 작성(LLM이 쓰고 코드 검증을 통과할 때만 사용)을 만들었습니다.

### 프론트와 안전 규칙 화면

- 예전 대시보드에 흩어져 있던 AI 7개를 AXcellent 사이드바 탭으로 옮기고 디자인을 맞췄습니다.
- 장애 대응 탭이 DejaFix의 실제 장애를 로그인 프록시로 받아 오게 하고, 가장 급한 장애, 요약, 시간대 분포, 비슷한 과거 장애 카드를 붙였습니다.
- AI 대화방에서 안전규칙 AI에게 직접 말을 걸고, 최근 판단을 날짜별로 고를 수 있게 했습니다.
- 요청마다 회사를 서버가 정하도록 공용 회사 범위(company scope)를 만들어 여러 회사 구조를 마무리했습니다.

### 성능 개선

- 재무 화면을 페이지별 코드 나누기, 뼈대 화면, 겹친 요청 막기, 장애 목록 N+1 제거로 빠르게 했습니다.
- 같은 장부로 만든 응답은 기억해 두고, 대화방을 열면 재무 AI의 답을 미리 만들어 둡니다.
- Lighthouse 기준 성능 66 → 94, 접근성 97 → 100, SEO 92 → 100이 됐습니다. 첫 화면 표시(FCP)는 2.7초에서 0.8초로, 가장 큰 요소 표시(LCP)는 3.4초에서 1.6초로 줄었습니다.
