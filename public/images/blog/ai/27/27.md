## 🦮 에이전트 9개를 돈 안 내고 인터넷에 올린 방법

인쇄 검수 앱 **PrintGuard-AI**를 만들어 두고 내 PC에서만 돌리고 있었다. 링크 하나로 남에게 보여 주고 싶어서 오늘은 배포를 했다. 조건은 하나, **돈을 내지 않는 것**이다.

결론부터 적으면 이렇게 됐다.

```text
브라우저 ─▶ Vercel(화면) ─▶ pg.2taeyoon.com ─▶ Cloudflare 터널 ─▶ 내 PC 127.0.0.1:8700 ─▶ 에이전트 9개
```

화면은 Vercel에 올리고, 에이전트는 **내 PC에서 돌리면서 터널로 인터넷에 창구만 하나 냈다.** 도메인은 원래 블로그가 쓰던 것을 Cloudflare로 옮겨 재활용했다. 카드 등록 없이 전부 $0이다.

### 🦄 먼저 알아 두면 좋은 용어

| 용어 | 쉽게 말하면 |
|---|---|
| 에이전트 | 맡은 일을 스스로 처리하는 AI 프로그램. 이 앱에서는 "색 담당", "종이 담당"처럼 역할 하나를 맡은 프로그램 |
| A2A (Agent-to-Agent) | 에이전트끼리 직접 일을 부탁하고 결과를 돌려주는 방식 |
| 오케스트레이터 | 일을 나눠 보내고 결과를 모으는 총괄 담당. 바깥에서 들어오는 창구이기도 하다 |
| DNS | 도메인 이름(`2taeyoon.com`)을 실제 서버 주소로 바꿔 주는 전화번호부 |
| 네임서버 | 그 전화번호부를 들고 있는 곳. 도메인마다 "내 번호부는 여기 있다"고 지정해 둔다 |
| 터널 | 공인 주소가 없는 내 PC를, 바깥에서 들어올 수 있게 중간에서 이어 주는 통로 |
| 서버리스 | 요청이 올 때만 깨어나 처리하고 꺼지는 방식. 평소에 켜 둘 필요가 없어 싸다 |

## 🦮 1. 올리려는 것이 좀 까다로웠다

이 앱은 검사 방식이 두 가지다.

| | 바로 검사 | 에이전트 검사 |
|---|---|---|
| 계산하는 곳 | 브라우저 안 | 에이전트 9개 |
| PDF | 어디로도 안 보냄 | 에이전트로 올라감 |
| 필요한 것 | 없음 | 에이전트가 켜져 있어야 함 |

**바로 검사는 배포가 쉽다.** 전부 브라우저에서 도니까 정적 파일만 올리면 끝이다. 문제는 에이전트 검사다.

에이전트는 파이썬 6개 + Node 3개, 총 9개가 포트 `8700`~`8708`에서 **계속 떠 있으면서 서로 http로 부른다.** 총괄이 사전 검사를 부르고 사전 검사가 안전 관문에 허가를 받고 그 결과를 다시 총괄이 모으는 식이다.

그래서 **서버리스로는 못 올린다.** 요청이 올 때만 깨는 함수로는 "옆 에이전트를 부른다"가 성립하지 않는다. 9개가 같이 떠 있어야 한다. 메모리도 전부 합치면 1GB 안팎이다.

## 🦮 2. 무료 호스팅을 찾다가 막힌 세 곳

처음 계획은 Hugging Face의 Docker Space였다. 컨테이너 하나에 9개를 담는 `Dockerfile`까지 다 써 뒀는데, 막상 Space를 만들려니 이렇게 떴다.

```text
Paid — Add billing to your account (credits or subscribe to PRO) to unlock Docker Spaces
```

무료로 남은 건 **정적 Space와 Gradio**뿐이다. Gradio는 파이썬만 돌아서 Node 에이전트 3개를 띄울 수 없다. 여기서 접었다.

### 🦄 ngrok — 고정 주소는 주는데 한도가 안 맞았다

ngrok 무료 플랜에는 고정 주소가 하나 딸려 온다. 그런데 나머지 한도가 문제였다.

| 항목 | 무료 한도 |
|---|---|
| HTTP 요청 | **월 2만 건** |
| 대역폭 | 월 1GB |
| 경고 페이지 | 붙음 |

우리 화면은 에이전트 상태를 5초마다, 소통 기록을 2초마다 확인한다. **탭 하나만 열어 둬도 분당 42건, 시간당 약 2,500건**이다. 8시간이면 한 달 치를 다 쓴다.

경고 페이지도 걸린다. 브라우저가 그 주소를 처음 부르면 ngrok 안내 화면이 먼저 뜨는데, 우리 코드는 JSON 대신 그 HTML을 받아 버린다.

### 🦄 그 밖에 본 것들

| 후보 | 왜 안 됐나 |
|---|---|
| Render 무료 | 512MB·0.1 CPU에 15분 유휴 시 잠듦. 9개가 안 들어간다 |
| Koyeb | 2026년 2월에 카드 없는 무료 플랜이 없어졌다 |
| Oracle Always Free | 2026년 6월에 한도가 반토막(약 2 OCPU/12GB). 돌릴 수는 있지만 카드가 필요하다 |
| Google Cloud Run | 월 200만 요청·18만 vCPU초 무료는 유지. 다만 카드 등록 + 콜드 스타트 수십 초 |

결국 **"무료로 24시간 떠 있는 서버"는 사실상 없어졌다.** 그래서 방향을 바꿨다. 서버를 빌리지 말고, **이미 있는 내 PC를 서버로 쓰자.**

## 🦮 4. 에이전트는 내 PC + 터널

### 🦄 임시 터널로 먼저 붙여 봤다

Cloudflare의 임시 터널은 명령 한 줄이면 주소를 하나 내준다.

```text
cloudflared tunnel --url http://127.0.0.1:8700
→ https://boards-inspired-fits-number.trycloudflare.com
```

이걸 Vercel 환경변수 `NEXT_PUBLIC_PG_ORCHESTRATOR`에 넣으니 바로 붙었다. 그런데 **임시 터널은 켤 때마다 주소가 바뀐다.** 그리고 `NEXT_PUBLIC_`으로 시작하는 값은 **빌드할 때 번들에 박혀서** 주소를 바꾸려면 재배포를 해야 한다. 터널 한 번 껐다 켤 때마다 재배포라니 쓸 수가 없다.

### 🦄 그래서 화면에서 주소를 바꿀 수 있게 했다

주소를 세 단계로 찾게 고쳤다.

```text
화면에서 저장한 주소(이 브라우저에만) → 빌드할 때 박힌 값 → 내 PC(127.0.0.1:8700)
```

`localStorage`에 저장하니 재배포 없이 즉시 바뀐다. 이걸로 급한 불은 껐는데, 켤 때마다 주소를 복사해 붙여넣는 건 여전히 귀찮았다.

### 🦄 CORS 한 줄

브라우저가 `vercel.app`에서 터널 주소를 부르면 **다른 출처**라 막힌다. 오케스트레이터에 그 출처를 허용해 줘야 한다.

```ini
PG_CORS_ORIGIN_REGEX=https://.*\.vercel\.app|http://(127\.0\.0\.1|localhost):\d+
```

> **CORS**는 "A 사이트의 코드가 B 서버를 불러도 되는가"를 브라우저가 확인하는 규칙이다. 서버가 "이 출처는 괜찮다"고 응답 헤더로 알려 줘야 통과한다.

## 🦮 5. 도메인을 Cloudflare로 옮겨 주소를 고정했다

### 🦄 내 도메인이면 주소를 고정할 수 있다

Cloudflare의 **이름 있는 터널**을 쓰면 `pg.내도메인.com` 같은 주소를 영구히 붙일 수 있다. 조건은 **DNS를 Cloudflare가 맡는 것**이다. 도메인을 어디서 샀는지는 상관없다.

마침 블로그가 쓰는 `2taeyoon.com`이 있었다. 호스팅케이알에서 산 도메인인데, **네임서버만 Cloudflare 것으로 바꾸면** 된다.

### 🦄 블로그를 안 끊고 넘기는 순서

살아 있는 블로그의 DNS를 옮기는 거라 순서가 중요했다. 기존 레코드를 먼저 확인해 보니 두 개뿐이었다.

| 이름 | 형식 | 값 |
|---|---|---|
| `2taeyoon.com` | A | `216.198.79.1` |
| `www` | CNAME | `...vercel-dns-017.com` |

메일(MX)도 TXT도 없었다. 옮길 게 적어서 다행이었다.

1. Cloudflare에 도메인을 추가한다 (Free 플랜). 기존 레코드를 자동으로 긁어 온다
2. 긁어 온 레코드가 맞는지 확인하고 **먼저 저장해 둔다**
3. 그다음에 호스팅케이알에서 네임서버를 바꾼다

이 순서면 네임서버가 바뀌는 순간 Cloudflare에 이미 같은 레코드가 있으니 **끊기는 구간이 없다.** 반대로 하면 그 사이에 블로그가 죽는다.

<img src="/images/blog/ai/27/images1.webp"/>

### 🦄 구름은 회색으로 둬야 한다

Cloudflare는 레코드마다 **프록시 상태**를 고를 수 있다. 주황 구름은 트래픽이 Cloudflare를 통과한다. 회색 구름은 DNS만 알려 주고 통신은 직접 간다.

블로그는 Vercel이 자기 인증서로 서비스하니 **주황 구름으로 두면 인증서가 부딪힌다.** 그래서 A와 CNAME 둘 다 **회색 구름(DNS 전용)** 으로 뒀다. "보호가 완전하지 않다"는 경고가 뜨지만 의도한 설정이다.

위 캡처에서 `pg.2taeyoon.com`만 주황 구름인데, **터널 레코드는 Cloudflare를 반드시 지나야 하므로** 이쪽은 프록시가 맞다.

### 🦄 네임서버 교체

```text
ns1~4.hosting.co.kr  →  harmony.ns.cloudflare.com, mitch.ns.cloudflare.com
```

호스팅케이알 화면에서 기존 4개를 지우고 2개를 넣었다. 중간에 입력칸이 "IP가 존재하지 않습니다"라며 저장을 막았는데, **타이핑 중간에 검사가 돌아서 생긴 오탐**이었다. 마지막 글자를 지웠다 다시 치니 "정상"으로 바뀌었다.

<img src="/images/blog/ai/27/images2.webp"/>

전파는 거의 즉시 끝났다. 공개 DNS(8.8.8.8)에 바로 Cloudflare 네임서버가 뜨고 블로그도 그대로 200을 돌려줬다.

## 🦮 6. 여기서 한참 막혔다

### 🦄 Authorize를 눌러도 아무 일이 없었다

터널을 만들려면 먼저 `cloudflared tunnel login`으로 인증을 받아야 한다. 브라우저가 열리고 도메인을 고르면 **Authorize** 버튼이 나오는데, 눌러도 화면이 그대로였다. 오류 메시지도 없었다.

눈으로 보이는 게 없으니 **응답 본문을 직접 까 봤다.** 브라우저의 `fetch`를 잠깐 가로채서 실패한 응답을 모았다.

```js
const of_ = window.fetch;
window.fetch = async function(...a) {
  const r = await of_.apply(this, a);
  // 실패한 토큰 발급 요청만 본문을 모아 둔다
  return r;
};
```

나온 답은 이랬다.

```json
{"success":false,"errors":[{"code":1211,"message":"Please verify your email."}]}
```

**계정 이메일 인증이 안 돼 있었다.** 대시보드 배너는 이미 사라져 있어서 겉으로는 인증된 것처럼 보였는데, API 기준으로는 아니었다. 인증 메일을 다시 보내 링크를 누르니 **한 번에 통과**했다.

> 화면에 오류가 안 뜨면 "안 되네"로 끝나기 쉽다. 그런데 실패한 요청의 **응답 본문에는 대부분 이유가 적혀 있다.** 이번처럼 한 줄이면 끝나는 문제도 많다.

### 🦄 Zero Trust는 Free인데 카드를 요구했다

인증이 막혔을 때 우회로로 **Zero Trust 대시보드에서 터널을 만드는 방법**을 봤다. 플랜 선택 화면에 `Zero Trust Free $0/seat/month`가 있어서 골랐더니, 다음 화면이 **결제수단 등록**이었다. $0인데도 카드를 먼저 받아 둔다.

카드 등록 없이 가는 게 목표라 이 길은 접었다. 이메일 인증만 하면 `tunnel login` 쪽이 깔끔하게 된다.

## 🦮 7. 터널 붙이고 확인

이름 있는 터널은 처음 세 줄이면 만들어진다.

```text
cloudflared tunnel login
cloudflared tunnel create printguard
cloudflared tunnel route dns printguard pg.2taeyoon.com
```

설정 파일에는 **오케스트레이터 하나만 열고 나머지는 전부 막았다.** 에이전트 8개는 PC 안에서만 서로 부르면 되지, 바깥에 열 이유가 없다.

```yaml
ingress:
  - hostname: pg.2taeyoon.com
    service: http://127.0.0.1:8700
  - service: http_status:404
```

Vercel 환경변수를 이 고정 주소로 바꾸고 재배포했다.

```text
python agents/run_agents.py
```

공개 사이트에 들어가니 **에이전트 8/8 정상**으로 붙었다.

## 🦮 8. 주소가 고정되니 만들었던 기능이 필요 없어졌다

4번에서 만든 '에이전트 주소' 입력칸은 주소가 고정된 지금 평소에 보일 이유가 없다. 그렇다고 지우면 터널이나 도메인에 문제가 생겼을 때 손쓸 방법이 사라진다.

그래서 **연결이 끊겼을 때만 나타나게** 했다. 평소에는 안 보이고 "에이전트가 꺼져 있습니다"가 뜰 때만 아래에 입력칸이 열린다.

연결 실패 문구도 같이 고쳤다. 전에는 "터널을 다시 켜면 주소가 바뀝니다"라고 안내했는데, 이름 있는 터널로 바꾼 뒤로는 **틀린 말**이 됐다.

> 급해서 만든 기능이 다음 날 필요 없어지는 일은 흔하다. 지울지 둘지 고를 때는 **그게 없으면 막히는 상황이 있는지**를 기준으로 삼는다. 대개 "조건부로 두기"가 답이 된다.

| 에이전트 | 내 PC | 전기료와 집 인터넷 업로드 |
| 도메인 | 원래 쓰던 것 | 연 갱신비(이미 내고 있던 것) |

A2A 호출을 아무리 많이 해도 **에이전트끼리의 통신은 전부 내 PC 안(`127.0.0.1`)에서** 일어난다. Cloudflare를 지나는 건 바깥에서 오케스트레이터를 부르는 요청 하나뿐이고 여기엔 요청 수 제한이 없다. ngrok이 월 2만 건에서 막히던 것과 갈리는 지점이다.

돈이 나가려면 **플랜 업그레이드나 결제수단 등록을 직접 눌러야** 한다. Zero Trust 활성화, Workers·R2 같은 유료 제품, Cloudflare Registrar로 도메인 이전 등이다.

### 🦄 대신 포기한 것

- **PC가 꺼지면 에이전트 검사도 멈춘다.** 사이트와 바로 검사 모드는 그대로 돌지만 에이전트 모드는 "꺼져 있습니다"가 된다
- **PDF가 내 PC로 올라온다.** 남이 올린 파일이 내 집 컴퓨터로 들어오는 구조라, 보여 줄 때만 터널을 켜는 편이 낫다
- **ICC 프로파일은 공개 사이트에 못 올린다.** 재배포가 허용되지 않는 파일이라, 색 차이를 재려면 방문자가 인쇄소에서 받은 `.icc`를 직접 올려야 한다

## 🦮 오늘 배운 것

**무료 서버를 찾는 것보다 이미 가진 것을 쓰는 쪽이 빨랐다.** Hugging Face·ngrok·Render·Oracle을 차례로 보면서 반나절을 썼는데, 답은 "내 PC를 서버로 쓰고 통로만 뚫자"였다.

**화면에 오류가 없다고 원인이 없는 건 아니다.** Authorize 버튼이 먹통이던 건 이메일 인증 한 줄이었고 응답 본문을 까 보니 `code 1211`이 그대로 적혀 있었다.

**무료라고 적혀 있어도 조건을 봐야 한다.** Zero Trust Free는 $0인데 카드를 요구하고, ngrok 무료는 고정 주소를 주면서 월 2만 요청으로 막는다. "무료"보다 **"내 사용 패턴에서 무료인가"** 가 중요하다.
