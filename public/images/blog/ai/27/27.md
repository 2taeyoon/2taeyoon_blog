## 🦮 화면만 배포하고 에이전트 9개는 내 PC에 남겼다

인쇄 검수 앱 **PrintGuard-AI**를 만들어 두고 내 PC에서만 돌리고 있었다. 링크 하나로 남에게 보여 주고 싶어서 오늘 공개 환경을 만들었다. 조건은 하나, **돈을 내지 않는 것**이다.

결론부터 적으면 이렇게 됐다.

```text
브라우저 ─> Vercel(화면) ─> pg.2taeyoon.com ─> Cloudflare 터널 ─> 내 PC 127.0.0.1:8700 ─> 에이전트 9개
```

화면은 Vercel에 올리고, 에이전트는 **내 PC에서 돌리면서 터널로 오케스트레이터 하나만 바깥에 열었다.** 도메인은 원래 블로그가 쓰던 것을 Cloudflare로 옮겨 재활용했다. 카드 등록 없이 전부 $0이다.

### 🦄 먼저 알아 두면 좋은 용어

| 용어 | 쉽게 말하면 |
|---|---|
| 에이전트 | 맡은 일을 스스로 처리하는 AI 프로그램. 이 앱에서는 "색 담당", "종이 담당"처럼 역할 하나를 맡은 프로그램 |
| A2A (Agent-to-Agent) | 에이전트끼리 직접 일을 부탁하고 결과를 돌려주는 방식 |
| 오케스트레이터 | 일을 나눠 보내고 결과를 모으는 총괄 담당. 바깥 요청도 여기로만 받는다 |
| DNS | 도메인 이름을 실제 서버 IP로 바꿔 주는 조회 체계 |
| 네임서버 | 그 도메인의 DNS 레코드를 보관하고 응답하는 서버. 도메인마다 어느 네임서버를 쓸지 지정해 둔다 |
| 터널 | 공인 IP가 없는 내 PC를 바깥에서 접속할 수 있게 중계해 주는 연결 |
| 서버리스 | 요청이 올 때만 실행되고 끝나면 종료되는 방식. 평소에 켜 둘 필요가 없다 |

## 🦮 1. 올리려는 것이 좀 까다로웠다

이 앱은 검사 방식이 두 가지다.

| | 바로 검사 | 에이전트 검사 |
|---|---|---|
| 계산하는 곳 | 브라우저 안 | 에이전트 9개 |
| PDF | 어디로도 안 보냄 | 에이전트로 올라감 |
| 필요한 것 | 없음 | 에이전트가 켜져 있어야 함 |

**바로 검사는 배포가 쉽다.** 전부 브라우저에서 도니까 정적 파일만 올리면 끝이다. 문제는 에이전트 검사다.

에이전트는 파이썬 6개 + Node 3개, 총 9개가 포트 `8700`~`8708`에서 **계속 떠 있으면서 서로 http로 부른다.** 총괄이 사전 검사를 부르고 사전 검사가 안전 관문에 허가를 받고 그 결과를 다시 총괄이 모으는 식이다.

그래서 **서버리스로는 못 올린다.** 요청이 올 때만 실행되는 함수로는 "옆 에이전트를 부른다"가 성립하지 않는다. 9개가 같이 떠 있어야 한다. 메모리도 전부 합치면 1GB 안팎이다.

## 🦮 3. 에이전트는 내 PC + 터널

### 🦄 임시 터널로 먼저 붙여 봤다

Cloudflare의 임시 터널은 명령 한 줄이면 주소를 하나 내준다.

```text
cloudflared tunnel --url http://127.0.0.1:8700
→ https://boards-inspired-fits-number.trycloudflare.com
```

이걸 Vercel 환경변수 `NEXT_PUBLIC_PG_ORCHESTRATOR`에 넣으니 바로 붙었다. 그런데 **임시 터널은 켤 때마다 주소가 바뀐다.** 그리고 `NEXT_PUBLIC_`으로 시작하는 값은 **빌드할 때 번들에 박혀서** 주소를 바꾸려면 재배포를 해야 한다. 터널 한 번 껐다 켤 때마다 재배포라니 쓸 수가 없다.

### 🦄 그래서 화면에서 주소를 바꿀 수 있게 했다

```text
화면에서 저장한 주소(이 브라우저에만) → 빌드할 때 박힌 값 → 내 PC(127.0.0.1:8700)
```

`localStorage`에 저장하니 재배포 없이 즉시 바뀐다. 이걸로 급한 불은 껐는데, 켤 때마다 주소를 복사해 붙여넣는 건 여전히 귀찮았다.

### 🦄 CORS 한 줄

브라우저가 `vercel.app`에서 터널 주소를 부르면 **다른 출처**라 막힌다. 오케스트레이터에 그 출처를 허용해 줘야 한다.

```ini
PG_CORS_ORIGIN_REGEX=https://.*\.vercel\.app|http://(127\.0\.0\.1|localhost):\d+
```

> **CORS**는 "A 사이트의 코드가 B 서버를 불러도 되는가"를 브라우저가 확인하는 규칙이다. 서버가 "이 출처는 괜찮다"고 응답 헤더로 알려 줘야 통과한다.

### 🦄 이건 A2A를 제대로 배포한 모습은 아니다

짚고 가면, A2A는 원래 **에이전트마다 공개 주소와 에이전트 카드가 있어서** 서로를 찾아가는 방식이다. 남이 만든 에이전트가 내 교정 담당을 직접 부를 수 있어야 제값을 한다.

여기서는 9개가 전부 내 PC 안(`127.0.0.1`)에 있고 바깥으로 열린 건 오케스트레이터 하나뿐이다. 밖에서는 교정 담당이 있는지도 모르고, **내 PC가 꺼지면 같이 꺼진다.**

그러니 이건 운영 배포가 아니라 **보여 주기 위한 환경**이다. 제대로 하려면 에이전트마다 주소와 인증을 붙여 각자 돌아가게 둬야 하는데, 그 순간 "돈을 내지 않는다"는 조건이 깨진다. 이번 목표는 거기가 아니었다.

## 🦮 4. 도메인을 Cloudflare로 옮겨 주소를 고정했다

### 🦄 내 도메인이면 주소를 고정할 수 있다

Cloudflare의 **이름 있는 터널**을 쓰면 `pg.내도메인.com` 같은 주소를 영구히 붙일 수 있다. 조건은 **DNS를 Cloudflare가 맡는 것**이다. 도메인을 어디서 샀는지는 상관없다.

마침 블로그가 쓰는 `2taeyoon.com`이 있었다. 호스팅케이알에서 산 도메인인데, **네임서버만 Cloudflare 것으로 바꾸면** 된다.

### 🦄 블로그를 안 끊고 넘기는 순서

살아 있는 블로그의 DNS를 옮기는 거라 순서가 중요했다. 기존 레코드를 먼저 확인해 보니 두 개뿐이었다.

| 이름 | 형식 | 값 |
|---|---|---|
| `2taeyoon.com` | A | `216.198.xx.xx` (Vercel) |
| `www` | CNAME | `...vercel-dns-017.com` |

메일(MX)도 TXT도 없었다.

1. Cloudflare에 도메인을 추가한다 (Free 플랜). 기존 레코드를 자동으로 긁어 온다
2. 긁어 온 레코드가 맞는지 확인하고 **먼저 저장해 둔다**
3. 그다음에 호스팅케이알에서 네임서버를 바꾼다

이 순서면 네임서버가 바뀌는 순간 Cloudflare에 이미 같은 레코드가 있으니 **끊기는 구간이 없다.** 반대로 하면 그 사이에 블로그가 죽는다.

<img src="/images/blog/ai/27/images1.webp"/>

### 🦄 프록시는 회색으로 둬야 한다

Cloudflare는 레코드마다 **프록시 상태**를 고를 수 있다. 주황 프록시는 트래픽이 Cloudflare를 통과한다. 회색 프록시는 DNS만 알려 주고 통신은 직접 간다.

블로그는 Vercel이 자기 인증서로 서비스하니 **주황 프록시로 두면 인증서가 부딪힌다.** 그래서 A와 CNAME 둘 다 **회색 프록시(DNS 전용)** 으로 뒀다. "보호가 완전하지 않다"는 경고가 뜨지만 의도한 설정이다.

위 캡처에서 `pg.2taeyoon.com`만 주황 프록시인데, **터널 레코드는 Cloudflare를 반드시 지나야 하므로** 이쪽은 주황 프록시가 맞다.

### 🦄 네임서버 교체

```text
xx1~4.hosting.co.kr  →  xxxx.ns.cloudflare.com, xxxx.ns.cloudflare.com
```

호스팅케이알 화면에서 기존 4개를 지우고 2개를 넣었다. 중간에 입력칸이 "IP가 존재하지 않습니다"라며 저장을 막았는데, **타이핑 중간에 검사가 돌아서 생긴 오탐**이었다. 마지막 글자를 지웠다 다시 치니 "정상"으로 바뀌었다.

<img src="/images/blog/ai/27/images2.webp"/>

전파는 거의 즉시 끝났다. 공개 DNS(8.8.8.8)에 바로 Cloudflare 네임서버가 뜨고 블로그도 그대로 200을 돌려줬다.

## 🦮 5. 터널 붙이고 확인

이름 있는 터널은 처음 세 줄이면 만들어진다.

```text
cloudflared tunnel login
cloudflared tunnel create printguard
cloudflared tunnel route dns printguard pg.2taeyoon.com
```

설정 파일에는 **오케스트레이터 하나만 열고 나머지는 전부 막았다.** 에이전트 8개는 PC 안에서만 서로 부르면 되지, 바깥에 열 이유가 없다.

```yaml
ingress:
  - hostname: pg.2taeyoon.com
    service: http://127.0.0.1:8700
  - service: http_status:404
```

Vercel 환경변수를 이 고정 주소로 바꾸고 재배포했다.

<img src="/images/blog/ai/27/images3.webp"/>

이제 켤 때마다 할 일은 두 줄이다.

```text
python agents/run_agents.py
cloudflared tunnel run printguard
```

공개 사이트에 들어가니 **에이전트 8/8 정상**으로 붙었다.

## 🦮 6. 주소가 고정되니 만들었던 기능이 필요 없어졌다

4번에서 만든 '에이전트 주소' 입력칸은 주소가 고정된 지금 평소에 보일 이유가 없다. 그렇다고 지우면 터널이나 도메인에 문제가 생겼을 때 손쓸 방법이 사라진다.

그래서 **연결이 끊겼을 때만 나타나게** 했다. 평소에는 안 보이고 "에이전트가 꺼져 있습니다"가 뜰 때만 아래에 입력칸이 열린다.

연결 실패 문구도 같이 고쳤다. 전에는 "터널을 다시 켜면 주소가 바뀝니다"라고 안내했는데, 이름 있는 터널로 바꾼 뒤로는 틀린 말이 됐다.
