
## 🦮 AI 에이전트 사고, 행동, 관찰 루프, smolagents

허깅페이스(Hugging Face)에서 제공하는 무료 AI 에이전트 코스를 수강하고 있습니다.

이번 글에서는 **AI 에이전트가 내부적으로 어떻게 동작하는지** 정리하고, 마지막에는 `smolagents` 라이브러리를 활용해 직접 첫 번째 에이전트를 구현합니다.

강의 분량이 상당히 많아 핵심 개념과 동작 원리를 중심으로 정리했습니다. 또한 강의 자료에서 다소 부정확하게 설명된 부분도 함께 짚어보겠습니다.

먼저 전체 내용을 한 문장으로 요약하면 다음과 같습니다.

> 에이전트는 LLM이 다음 행동을 결정하고, 정해진 형식으로 도구 호출을 요청하면, 외부 실행 환경이 해당 요청을 처리하고 결과를 다시 전달하는 과정을 반복하는 구조입니다.

## 🦮 1. 전체 구조: 사고 → 행동 → 관찰 루프

AI 에이전트는 일반적으로 `while` 반복문과 유사한 구조로 동작합니다. 사용자가 제시한 목표를 달성하거나 작업을 종료할 조건을 만족할 때까지 다음 세 단계를 반복합니다.

| 단계 | 역할 | 설명 |
|---|---|---|
| 사고(Thought) | 판단 및 계획 | LLM이 현재 상황을 분석하고 다음 행동을 결정합니다. |
| 행동(Action) | 도구 호출 | 필요한 도구를 선택하고 적절한 인자를 전달합니다. |
| 관찰(Observation) | 결과 확인 | 도구가 반환한 결과를 받아 다음 판단에 활용합니다. |

이러한 반복 과정을 제어하기 위해 시스템 프롬프트에는 사용할 수 있는 도구 목록, 출력 형식, 행동 규칙 등이 정의됩니다.

### 🦄 예시: 날씨를 알려주는 에이전트 Alfred

사용자가 "뉴욕 날씨 어때?"라고 요청했다고 가정해 보겠습니다.

1. **사고:** Alfred가 요청을 분석하고 날씨 정보가 필요하다고 판단합니다.
2. **행동:** `get_weather` 도구를 선택하고 뉴욕을 인자로 전달합니다.
3. **관찰:** 날씨 도구가 "흐림, 15°C"라는 결과를 반환합니다.
4. **최종 응답:** 반환된 정보를 바탕으로 사용자에게 날씨를 알려주고 작업을 종료합니다.

이처럼 에이전트는 단순히 답변을 생성하는 데 그치지 않고, 필요한 정보를 직접 수집하고 결과를 확인하면서 목표를 달성합니다.

## 🦮 2. 사고(Thought): 에이전트의 내부 추론

사고는 에이전트가 현재 상황을 분석하고 다음에 수행할 작업을 결정하는 과정입니다. 복잡한 문제를 작은 단계로 나누고, 새로운 정보가 들어오면 기존 계획을 수정하기도 합니다.

### 🦄 ReAct 방식

**ReAct는 Reasoning(추론)과 Acting(행동)을 결합한 개념**입니다.

LLM이 추론과 행동을 번갈아 수행하도록 설계한 방식으로, 단순히 생각만 이어가거나 무작정 도구를 호출하는 대신 다음과 같은 흐름을 만듭니다.

**추론 → 행동 → 관찰 → 재추론**

도구를 실행한 결과를 확인한 뒤 다음 행동을 결정한다는 점이 핵심입니다.

### 🦄 추론 모델은 접근 방식이 다릅니다

DeepSeek R1이나 OpenAI o1과 같은 추론 모델은 복잡한 문제를 해결하기 위한 내부 추론 과정을 수행하도록 학습되었습니다.

일부 모델은 `\<think>`와 같은 별도의 추론 구간을 출력하기도 합니다. 이는 단순히 프롬프트에 생각을 유도하는 문장을 추가하는 방식과는 구분됩니다.

반면 함수 호출에 최적화된 모델은 별도의 추론 과정을 명시적으로 출력하지 않고 곧바로 도구 호출을 생성하기도 합니다.

### 🦄 강의 내용에서 바로잡을 점 두 가지

한국어 강의 자료에는 ReAct에 대한 설명 중 수정할 부분이 있었습니다.

1. ReAct를 "강화학습(Reinforcement Learning) + 행동"이라고 설명한 부분이 있는데, 정확한 의미는 **Reasoning + Acting(추론 + 행동)**입니다.
2. ReAct를 단순히 프롬프트에 "단계별로 생각해 보자"라는 문장을 추가하는 기법으로 설명한 부분이 있습니다. 이는 **Zero-shot CoT(사고의 사슬)**에 가까운 설명입니다. ReAct의 핵심은 추론과 도구 호출, 실행 결과에 대한 관찰을 반복하는 데 있습니다.

## 🦮 3. 행동(Action): 환경과 상호작용하기

행동은 에이전트가 외부 환경에 실제로 영향을 주거나 필요한 정보를 가져오는 단계입니다.

### 🦄 에이전트의 행동 표현 방식

| 유형 | 행동을 표현하는 방법 |
|---|---|
| JSON 에이전트 | 수행할 행동을 JSON 형식으로 출력합니다. |
| 코드 에이전트 | 실행 가능한 코드(주로 Python)를 생성합니다. |
| 함수 호출 에이전트 | 모델이 정의된 함수와 인자를 구조화된 호출 형태로 생성합니다. |

행동의 목적은 크게 다음과 같이 나눌 수 있습니다.

- **정보 수집:** API, 데이터베이스, 검색 도구 등을 통해 정보를 가져옵니다.
- **도구 사용:** 외부 라이브러리나 서비스를 호출합니다.
- **환경 조작:** 파일 생성, 데이터 수정, 시스템 명령 실행 등을 수행합니다.
- **의사소통:** 사용자나 다른 에이전트와 정보를 주고받습니다.

### 🦄 핵심 원리: 생성 중단 후 파싱(Stop & Parse)

에이전트가 도구를 호출하는 원리는 생각보다 단순합니다.

1. 모델이 정해진 형식(JSON 또는 코드)으로 행동을 출력합니다.
2. 행동에 필요한 내용을 모두 생성하면 모델의 출력을 중단합니다.
3. 외부 파서가 출력에서 도구 이름과 인자를 추출합니다.
4. 추출한 정보를 바탕으로 실제 도구를 실행합니다.

즉, 모델이 직접 도구를 실행하는 것이 아닙니다.

**모델은 실행 요청을 생성하고, 실제 실행은 외부 프로그램이 담당합니다.**

### 🦄 코드 에이전트의 장점

- **표현력:** 반복문과 조건문을 활용해 복잡한 작업 흐름을 표현할 수 있습니다.
- **재사용성:** 한 번 정의한 함수를 여러 작업에서 재사용할 수 있습니다.
- **디버깅:** 코드 형태이므로 오류가 발생한 위치와 원인을 추적하기 쉽습니다.
- **라이브러리 연동:** 기존 Python 라이브러리를 활용해 다양한 기능을 구현할 수 있습니다.

## 🦮 4. 관찰(Observation): 실행 결과를 확인하고 다음 행동 결정하기

관찰은 에이전트가 행동을 수행한 뒤 외부 환경으로부터 전달받는 결과입니다.

API 응답, 오류 메시지, 시스템 로그, 데이터베이스 조회 결과 등이 모두 관찰에 해당합니다.

관찰 단계에서는 주로 다음 세 가지 작업이 이루어집니다.

1. **피드백 수집:** 실행한 행동이 성공했는지 실패했는지 확인합니다.
2. **맥락 갱신:** 새롭게 얻은 정보를 기존 대화 및 실행 맥락에 추가합니다.
3. **전략 수정:** 갱신된 정보를 바탕으로 다음 사고와 행동을 결정합니다.

예를 들어 날씨 API가 다음과 같은 결과를 반환했다고 가정해 보겠습니다.

`구름 조금, 15°C, 습도 60%`

이 결과가 에이전트의 실행 맥락에 추가되면 LLM은 해당 정보를 바탕으로 추가적인 도구 호출이 필요한지, 아니면 최종 답변을 생성해도 되는지 판단합니다.

전체적인 처리 흐름은 다음과 같습니다.

**행동 생성 → 도구 호출 파싱 → 도구 실행 → 결과 수신 → Observation 추가 → 다음 추론**

이 과정을 반복하면서 에이전트는 목표를 달성하게 됩니다.

## 🦮 5. 더미 에이전트: 프레임워크 없이 직접 구현하기

강의에서는 에이전트 프레임워크가 내부적으로 어떤 작업을 대신 처리하는지 이해하기 위해, 먼저 Python만으로 간단한 에이전트를 구현합니다.

직접 만들어 보면 프레임워크가 제공하는 기능과 자동화 범위를 명확하게 이해할 수 있습니다.

### 🦄 시스템 프롬프트에 출력 형식 정의하기

먼저 시스템 프롬프트에 사용할 수 있는 도구 목록과 함께 다음과 같은 출력 형식을 지정합니다.

- `Thought`: 현재 상황에 대한 추론
- `Action`: 실행할 도구와 인자
- `Observation`: 도구 실행 결과
- `Final Answer`: 사용자에게 전달할 최종 답변

이렇게 하면 모델이 정해진 형식에 맞춰 행동을 생성하도록 유도할 수 있습니다.

### 🦄 문제점: 모델이 관찰 결과를 지어낼 수 있습니다

하지만 프롬프트에 출력 형식만 지정한다고 해서 모든 문제가 해결되는 것은 아닙니다.

모델이 실제로 도구를 실행하지 않았는데도 `Observation:` 뒤에 실행 결과를 임의로 생성할 수 있습니다.

이는 모델이 외부 환경의 실제 상태를 확인하지 않고 결과를 만들어 내는 환각(Hallucination)의 사례입니다.

이 문제를 방지하기 위해 강의에서는 `Observation:`이 출력되는 순간 모델의 생성을 중단하도록 설정합니다.

```python
output = client.chat.completions.create(
    messages=messages,
    max_tokens=150,
    stop=["Observation:"],  # Observation이 출력되기 전에 생성 중단
)
```

이후 외부 Python 코드에서 실제 함수를 실행하고, 그 결과를 다시 모델에 전달합니다.

전체 흐름은 다음과 같습니다.

1. 모델이 Thought와 Action을 생성합니다.
2. `Observation:`이 나오기 전에 생성을 중단합니다.
3. Python 코드가 Action을 파싱하고 해당 함수를 실행합니다.
4. 실제 함수 실행 결과를 Observation으로 추가합니다.
5. 갱신된 프롬프트를 모델에 다시 전달합니다.
6. 모델이 결과를 분석하고 최종 답변을 생성합니다.

즉, **모델이 관찰 결과를 임의로 만들어 내지 못하도록 실제 실행 결과만 외부에서 전달하는 구조**입니다.

직접 구현해 보면 생각보다 번거로운 작업이 많습니다. 이러한 과정을 자동으로 처리해 주는 것이 바로 에이전트 프레임워크입니다.

참고로 최근에는 모델 API 자체에서 함수 호출(Function Calling) 기능을 지원하기 때문에, 실무에서는 위와 같은 방식으로 문자열을 직접 중단하고 파싱하는 코드를 매번 작성할 필요가 없습니다.

다만 내부 동작 원리를 이해하기 위한 학습 과정에서는 상당히 유용한 예제입니다.

## 🦮 6. smolagents로 첫 번째 AI 에이전트 만들기

`smolagents`는 Hugging Face에서 개발한 경량 AI 에이전트 프레임워크입니다.

특히 **코드 에이전트(CodeAgent)**를 중심으로 설계되어 있으며, 모델이 실행 가능한 코드를 생성하고 외부 실행 환경에서 이를 처리하는 방식으로 동작합니다.

강의에서는 Hugging Face Spaces의 템플릿을 복제한 다음 `app.py`를 수정해 에이전트를 구현합니다.

### 🦄 도구(Tool) 만들기

`smolagents`에서는 `@tool` 데코레이터를 사용해 사용자 정의 도구를 만들 수 있습니다.

도구를 정의할 때는 다음 두 가지를 주의해야 합니다.

1. **타입 힌트(Type Hint):** 함수의 입력값과 반환값에 대한 자료형을 명시해야 합니다.
2. **Docstring:** 도구의 역할과 각 인자의 의미를 구체적으로 설명해야 합니다.

예제 코드는 다음과 같습니다.

```python
from smolagents import tool

@tool
def my_custom_tool(arg1: str, arg2: int) -> str:
    """아직 아무 작업도 수행하지 않는 사용자 정의 도구입니다.

    Args:
        arg1: 첫 번째 인자입니다.
        arg2: 두 번째 인자입니다.
    """
    return "어떤 도구를 만들어 볼까요?"
```

에이전트는 함수의 타입 힌트와 Docstring을 참고해 해당 도구의 역할과 사용 방법을 파악합니다.

따라서 도구 설명을 구체적으로 작성하는 것이 중요합니다.

**도구의 설명이 명확할수록 에이전트가 해당 도구를 올바르게 선택하고 사용할 가능성이 높아집니다.**

### 🦄 모델과 에이전트 연결하기

모델은 `InferenceClientModel`을 사용해 Hugging Face에서 제공하는 추론 모델과 연결할 수 있습니다.

이후 직접 만든 도구를 `CodeAgent(tools=[...])`에 등록하면 에이전트가 해당 도구를 사용할 수 있게 됩니다.

여기서 중요한 부분은 **`final_answer` 도구입니다.**

`final_answer`는 에이전트가 작업을 마무리하고 최종 결과를 반환하는 데 사용되는 도구입니다. 강의 예제에서 제공하는 기본 도구 구성을 임의로 제거하면 최종 답변 처리에 문제가 발생할 수 있으므로 주의해야 합니다.
