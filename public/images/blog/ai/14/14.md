## 🦮 AX 개발: AGI, 임베딩, 개발 환경

좋은 기회로 참석하게 된 AX 개발자 특강을 다시 정리한 글이다.

**AX 개발의 시작**은 세 가지를 한 줄로 잇는 일이다. **AGI가 어떤 목표인지 알고, 임베딩으로 뜻의 가까움을 숫자로 다루며, 그 일을 내 윈도우 컴퓨터에서 직접 실행할 환경을 만든다.**

말로만 들은 AI와, 내 컴퓨터에서 사진이 들어가고 답이 나오는 AI는 다르다. 특강은 개념 두 개와 실습 준비 한 덩어리로 이루어져 있었다.

1. **AGI**를 지금 쓰는 AI, 연구 목표, 아직 가설인 단계로 나누어 들었다.
2. **임베딩**으로 글의 뜻을 숫자로 바꿔, 단어가 달라도 비슷한 글을 찾는다.
3. **개발 환경**으로 VS Code, Git, Miniforge, CUDA, PyTorch, 클로드 코드를 깔고, 일을 기록하고 나누는 규칙까지 세웠다.

아래는 그 세 덩어리를, 처음 보는 사람도 따라갈 수 있게 풀어 쓴 것이다.

## 🦮 1. AGI는 여러 분야의 문제를 푸는 인공지능이다

AGI(Artificial General Intelligence, 범용 인공지능)는 여러 분야의 문제를 이해하고, 새로 배우며, 풀어 내는 인공지능을 뜻한다. 사람 한 명이 글도 읽고, 그림도 보고, 처음 보는 규칙도 익히는 쪽에 가깝다.

길을 세 계단으로 부르면 지금 어디쯤인지 헷갈리지 않는다.

### 🦄 1.1. 세 계단: ANI, AGI, ASI

1. **ANI, 좁은 인공지능. 지금 흔히 보는 AI**

   하는 일의 범위가 정해져 있다. 번역, 이미지 만들기, 코드 작성, 음성 인식처럼 특정 작업에 맞춰져 있다. 계산기에 비유하면, 덧셈과 곱셈은 매우 빠른데 그 계산기가 요리를 대신 해 주지는 않는 상태다. 지금 일상에서 "AI"라고 부르는 대부분을 이 계단에 둔다.

2. **AGI, 범용 인공지능. 연구의 목표**

   분야가 바뀌어도 새 문제를 배우고 추론한다. 글, 그림, 계획, 도구 사용처럼 종류가 다른 일을 사람 수준에 가깝게 넘나드는 지적 능력을 목표로 한다. 학교 비유를 하면, 처음 보는 과목 안내문을 읽고 스스로 공부 방법을 만드는 쪽에 가깝다. 아직 "완제품이 여기 있다"고 모두가 가리키는 단계라기보다, 연구가 향하는 목표다.

3. **ASI, 초인공지능. 가설로 말하는 단계**

   과학, 공학, 전략처럼 거의 모든 지적 영역에서 사람의 능력을 크게 앞서는 AI를 가리킨다. 실험실에 설치되어 누구나 쓰는 제품의 이름이 아니다. 앞으로를 상상하며 이야기하는 계단이다.

| 이름 | 한 줄 | 특강에서 둔 위치 |
|---|---|---|
| ANI | 범위가 정해진 일을 수행한다 | 현재의 일반적인 AI |
| AGI | 여러 분야의 새 문제를 배우고 푼다 | 연구 목표 |
| ASI | 거의 모든 지적 영역에서 사람을 크게 앞선다 | 가설적 단계 |

### 🦄 1.2. 지금 쓰는 챗봇은 어느 계단인가

ChatGPT 같은 모델은 번역만 하거나 그림만 그리지 않는다. 설명도 하고, 코드도 작성하고, 긴 글도 요약한다. 할 수 있는 일의 종류가 넓다.

그래도 특강의 구분은 분명했다. **여러 일을 처리한다고 해서, 그 모델을 AGI로 부르자는 합의가 끝난 것은 아직이다.** 지금 단계는 ANI로 이해하고, AGI는 그다음을 향하는 연구 목표로 이해하면 된다.

외우는 문장은 이것이다. **지금은 좁은 AI가 매우 넓어지고 있고, 범용 인공지능은 목표이며, 초인공지능은 아직 가설이다.**

## 🦮 2. 임베딩은 뜻을 숫자 줄로 바꾸는 기술이다

임베딩(Embedding)은 딥러닝과 자연어 처리에서 자주 만나는 기술이다. AI 에이전트, LLM, RAG를 만들려면 이 개념이 먼저 필요하다.

한 줄로 말하면, **글이나 그림 같은 데이터를 AI가 계산하고 비교할 수 있도록 숫자 줄로 바꾸는 일**이다. 이 숫자 줄을 벡터(Vector)라고 부른다.

### 🦄 2.1. 컴퓨터는 문장을 눈으로 읽지 못한다

사람은 아래 두 문장을 보자마자 비슷한 말이라고 느낀다.

- "강아지가 귀엽다."
- "개가 사랑스럽다."

컴퓨터는 글자를 그대로 두고는 그 느낌을 계산하지 못한다. 임베딩 모델이 문장을 숫자 줄로 바꾼다.

```text
입력 텍스트  →  임베딩 모델  →  숫자 벡터
"강아지가 귀엽다."              [0.21, -0.43, 0.87, 0.12, ...]
```

예시에 숫자가 네 개만 보이지만, 실제 모델은 수백 개에서 수천 개 이상의 숫자를 한 줄로 만든다. 문장 하나가 아주 긴 좌표가 되는 셈이다.

지도 위에 점을 찍는다고 생각하면 된다. 문장이 점이다. 뜻이 비슷하면 점이 가까이 놓이고, 뜻이 멀면 점이 멀리 놓인다. "강아지가 귀엽다"의 점과 "개가 사랑스럽다"의 점은 가깝다. "오늘 주식 시장 전망"의 점은 멀리 있다.

각 숫자가 '귀여움 칸', '강아지 칸'처럼 사람이 칸마다 이름표를 붙여 둔 값은 아니다. **모델이 많은 글을 학습하면서, 데이터끼리의 관계로 자리 잡은 패턴**이다.

### 🦄 2.2. 핵심은 뜻이 가까우면 숫자도 가깝다는 점이다

검색창에 "강아지를 키우는 방법"을 넣었다고 하자. 저장해 둔 문장과 비교한 예시 점수는 아래와 같다. **개념을 보여 주려고 만든 점수다. 특정 모델의 실측값은 따로 재야 한다.**

| 비교 문장 | 예시 유사도 | 읽는 법 |
|---|---|---|
| 반려견을 기르는 방법 | 0.91 | 단어는 달라도 뜻이 매우 가깝다 |
| 강아지 사료 추천 | 0.76 | 같은 주제와 맞닿아 있다 |
| 오늘 주식 시장 전망 | 0.08 | 이야기 결이 다르다 |

"강아지"와 "반려견"은 글자가 다르다. 그래도 유사도가 높게 나온다. 글자가 똑같은 문서를 찾는 검색과 달리, **뜻으로 찾는 검색**이 된다. 이것을 의미 기반 검색(Semantic Search)이라고 부른다.

학교 도서부 비유를 하면 이렇다. 제목에 "강아지"가 없는 책도, 내용이 반려동물 돌봄이면 같은 선반 가까이 꽂힌다. 임베딩은 그 선반 위치를 숫자로 정하는 일이다.

### 🦄 2.3. 임베딩은 어디에 쓰나

1. **Vertor DB**

   숫자 줄을 저장하고, 비슷한 줄을 빨리 찾는다. 제품 이름으로 Pinecone, Qdrant, Chroma가 있다. 도서부 선반을 컴퓨터 안에 만든 것이라고 보면 된다.

2. **RAG, 검색 증강 생성**

   긴 문서를 임베딩해서 저장한다. 사용자가 질문하면 뜻이 가까운 문서를 찾고, 그 문서를 LLM에게 함께 건넨 뒤 답을 만들게 한다. 오픈북 시험과 같다. 책을 통째로 외우는 대신, 문제와 가까운 페이지를 펼치고 그 페이지를 보고 답을 쓴다. 페이지를 찾는 쪽이 임베딩이고, 페이지를 읽고 문장으로 답하는 쪽이 LLM이다.

3. **추천**

   어떤 사람이 고른 상품이나 글과 벡터 공간에서 가까운 항목을 골라 보여 준다. "이 간식을 집었으니, 옆 칸의 비슷한 간식도 보여 주자"와 같다.

예를 들어 정부 지원사업 안내문을 임베딩해 두면, "실업 상태인데 받을 수 있는 지원금이 있나요?"라는 질문에 단어가 그대로 겹치지 않아도 관련 안내문을 집어 올 수 있다.

### 🦄 2.4. 딥러닝, 임베딩, LLM은 역할이 다르다

세 단어가 한 문장에 자주 같이 나와서 하나로 섞이기 쉽다. 역할은 따로다.

| 개념 | 역할 | 쉬운 비유 |
|---|---|---|
| 딥러닝 (Deep Learning) | 신경망으로 패턴을 학습하는 방법 | 문제를 많이 풀어 요령을 익히는 연습 |
| 임베딩 (Embedding) | 데이터를 벡터로 나타내는 방식 | 뜻을 지도 위의 점으로 찍는 일 |
| LLM | 글을 이해하고 생성하도록 학습된 대규모 언어 모델 | 펼쳐진 페이지를 읽고 답을 쓰는 사람 |

임베딩은 딥러닝 모델이 학습한 결과로 만들어질 수 있다. 단어 임베딩인 Word2Vec은 단어 하나를 벡터로 배운다. 요즘의 문장 임베딩 모델은 문장 전체의 뜻을 벡터 하나로 나타낸다. 점의 단위가 단어에서 문장으로 커진 것이다.

### 🦄 2.5. 개발자가 서비스를 만들 때의 순서

AI 에이전트나 RAG 서비스를 만들 때 흐름은 보통 아래 다섯 칸이다.

1. **모으고 나눈다.** 문서를 수집하고, 너무 긴 글은 짧은 조각으로 나눈다. 이 나누기를 청킹(Chunking)이라고 한다. 두꺼운 안내문을 카드 크기로 정리하는 일이다.
2. **숫자로 바꾼다.** 임베딩 모델이 각 조각을 벡터로 만든다.
3. **보관한다.** Vector DB에 넣는다.
4. **가까운 카드를 찾는다.** 사용자 질문도 같은 방식으로 벡터로 바꾼 뒤, 가까운 문서를 검색한다.
5. **읽고 답한다.** LLM이 검색된 문서를 바탕으로 답변 문장을 만든다.

임베딩 한 줄 요약은 이것이다. **데이터의 뜻과 특징을 숫자 벡터로 나타내서, AI가 비슷한 것을 찾고 비교하게 하는 도구다.**

## 🦮 3. 개발 환경 설정

개념을 코드로 확인하려면 컴퓨터 안에 도구가 먼저 있어야 한다.

### 🦄 3.1. 설치하는 도구

도구는 역할이 다르다. 하나만 설치해서 끝나지 않는다.

| 구분 | 도구 | 하는 일 |
|---|---|---|
| GPU | 그래픽카드와 드라이버 | 덧셈과 곱셈을 많이, 동시에 처리한다 |
| GPU 계산 도구 | CUDA Toolkit | 프로그램이 그래픽카드에서 계산을 실행하게 한다 |
| 파이썬 환경 관리 | Miniforge | 파이썬 가상환경을 만들고 연다 |
| 작업용 환경 | 가상환경 dev, Python | 다른 프로젝트의 패키지와 섞이지 않게 분리한다 |
| 딥러닝 라이브러리 | PyTorch + cu126 | 딥러닝 모델을 만들고 실행한다 |
| 편집과 기록 | VS Code, Git | 코드를 쓰고, 변경 내용을 시간순으로 남긴다 |
| 코딩 에이전트 | 클로드 코드 | 설치와 코딩을 대화로 진행한다 |


### 🦄 3.2. 클로드 코드

클로드 코드(Claude Code)는 터미널이나 앱에서 대화하며 파일을 수정하고 명령을 실행하는 코딩 에이전트다. 특강에서는 CLI와 데스크톱 앱을 함께 설치했다.

1. **CLI (명령줄 프로그램)**

   명령을 입력해서 실행한다. 설치는 아래 한 줄이다. `&&`는 앞 명령이 성공하면 다음 명령으로 넘어간다.

   ```bat
   curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
   ```

   - `curl`은 URL에서 파일을 다운로드한다.
   - `-fsSL`은 실패하면 멈추고, 진행 표시를 줄이며, 리다이렉트를 따라가라는 옵션이다.
   - `-o install.cmd`는 받은 파일 이름을 `install.cmd`로 저장한다.
   - `install.cmd`는 그 설치 파일을 실행해서 클로드 코드를 설치한다.
   - `del install.cmd`는 설치가 끝난 뒤 받은 `install.cmd`만 삭제한다. 이미 설치된 `claude.exe`는 남는다.

   이 PC에서 확인된 프로그램 위치는 `C:\Users\403\.local\bin\claude.exe`이고, 버전은 Claude Code 2.1.296이다.

2. **환경 변수 Path에 설치 폴더를 등록한다**

   프로그램을 설치해도, Windows가 `claude`라는 명령과 실행 파일 경로를 연결하지 못하면 명령이 실패한다. Path는 실행 파일을 찾는 폴더 목록이다.

   목록에 `C:\Users\403\.local\bin`이 들어 있어야, 어느 폴더의 터미널에서든 `claude`만 입력해도 프로그램이 실행된다. Path를 수정한 뒤에는 **터미널을 새로 열어야** 변경된 값을 읽는다. 이미 열려 있던 창은 이전 Path를 유지하는 경우가 많다.

3. **데스크톱 앱**

   같은 에이전트를 GUI로 실행하는 프로그램이다. CLI는 터미널이고, 데스크톱 앱은 일반 창이다. 특강에서는 둘 다 준비했다. 기능은 같고, 사용하는 화면이 다르다.

```bat
claude --permission-mode dontAsk --dangerously-skip-permissions
```

- `claude`는 에이전트를 실행한다.
- `--permission-mode dontAsk`는 개별 권한 확인을 매번 묻지 않고 진행하는 모드다.
- `--dangerously-skip-permissions`는 파일 수정과 명령 실행 전의 권한 확인을 건너뛴다. 옵션 이름에 dangerously가 들어 있다. **컴퓨터에서, 어떤 파일을 수정해도 되는지 알고 쓸 때 쓰는 옵션**이다. 확인을 건너뛰므로 에이전트가 파일을 수정하고 프로그램을 실행할 수 있다. 다른 사람의 컴퓨터나, 내용을 잘 모르는 폴더에서는 켜 두지 않는다.

### 🦄 3.3. 설치 지시

도구를 하나씩 직접 설치하기보다, 클로드 코드에 설치를 맡겼다. 지시한 내용을 읽기 쉽게 다시 적으면 아래와 같다. 항목은 같다.

```text
이 윈도우 PC에 개발 환경을 세팅해 줘.
아래 목록을 받아서 설치까지 진행하고, 서로 겹치지 않는 일은 동시에 진행해 줘.

- VS Code 설치
- Git 설치
- Miniforge 설치
- CUDA 12.6 설치
- Miniforge로 Python 3.11 가상환경을 만들고, 그 환경에서 PyTorch 2.14.1 설치

가상환경을 켜서, PyTorch가 GPU를 쓸 수 있는지까지 확인해 줘.
```

실제로 쓰인 설치 명령은 Windows 앱 설치 도구인 `winget`과, Miniforge의 `conda`, 파이썬의 `pip`였다.

```bat
winget install --id CondaForge.Miniforge3
winget install --id Nvidia.CUDA --version 12.6 --silent
```

```bat
conda create -n dev python=3.11 -y
```

가상환경 `dev`를 활성화한 뒤:

```bat
pip install torch==2.14.1 torchvision torchaudio --index-url https://download.pytorch.org/whl/cu126
```

`cu126`은 CUDA 12.6용으로 빌드된 PyTorch 패키지라는 뜻이다. CUDA 12.6과 PyTorch cu126의 버전이 맞아야 GPU 계산이 된다.

### 🦄 3.4. 도구별 설명

1. **VS Code**

   Visual Studio Code는 코드를 편집하는 프로그램이다. 문법에 따라 색이 표시되고, 저장과 검색이 되며, 편집기 안에 터미널이 들어 있다.

   이번 확인 버전은 1.141.0이다. 사용자 범위로 설치해서, 이 사용자 계정에서 쓰도록 설치했다.

2. **Miniforge**

   파이썬(Python)은 AI 프로그램을 많이 작성하는 언어다. 파이썬용 추가 라이브러리를 패키지라고 부른다. 패키지를 프로젝트 구분 없이 설치하면, 프로젝트마다 필요한 버전이 충돌할 수 있다.

   Miniforge는 패키지와 파이썬 버전을 가상환경별로 관리하는 프로그램이다. 같은 계열의 배포판이 Anaconda이고, Miniforge는 그중 포함된 패키지가 적은 배포판이다. 가상환경을 만드는 명령이 `conda`다.

   이번 확인 버전은 Miniforge3 26.7.2, conda 26.7.2다. 설치 위치는 `C:\Users\403\miniforge3`다.

3. **가상환경 dev**

   가상환경은 컴퓨터 전체를 다시 설치하는 일이 아니다. **이 프로젝트만 쓰는 파이썬 환경**이다. 그 환경의 패키지는 다른 환경에 영향을 주지 않는다.

   만든 환경의 이름은 dev다.

   ```bat
   conda create -n dev python=3.11 -y
   conda activate dev
   ```

   - `create`는 가상환경을 만든다.
   - `-n dev`는 환경 이름을 dev로 정한다.
   - `python=3.11`은 그 환경의 파이썬 버전이다.
   - `-y`는 확인 질문에 미리 yes로 답한다.
   - `activate`는 이후 파이썬 명령을 이 환경에서 실행한다. 프롬프트 앞에 `(dev)`가 보이면 그 환경이 활성화된 것이다.

   확인된 파이썬은 3.11.17이고, 경로는 `C:\Users\403\miniforge3\envs\dev`다. 새 PowerShell 창에서 `conda`를 바로 쓰려면 `conda init powershell`이 필요할 수 있다. 이번 목록에서는 선택 항목으로 남아 있다.

5. **CUDA 12.6**

   CUDA는 엔비디아(NVIDIA)가 만든 기술이다. 프로그램이 GPU에서 계산을 실행할 때 쓰는 라이브러리와 도구다. 12.6은 그 버전이다.

   이번 설치본은 CUDA Toolkit 12.6.3이고, 컴파일러 `nvcc` 버전은 12.6.85다. 설치 경로는 `C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.6`이다. 환경 변수 `CUDA_PATH`도 그 폴더를 가리킨다.

   PyTorch cu126 설치 파일은 실행에 필요한 CUDA 라이브러리를 패키지에 포함하고 있다. GPU로 PyTorch를 실행하는 일과, 시스템에 CUDA Toolkit을 설치하는 일은 같지 않다. Toolkit의 `nvcc`는 CUDA 코드를 직접 컴파일할 때 쓴다. 특강 목록에 CUDA 12.6 설치가 있었기 때문에 Toolkit도 함께 설치했다.

   설치 프로그램이 그래픽 드라이버도 560.94에서 561.17로 올렸다. 드라이버는 Windows가 GPU를 인식하고 사용하게 하는 소프트웨어다. 드라이버가 CUDA 12.6을 지원해야 cu126 PyTorch가 GPU를 사용할 수 있다. 화면이 잠깐 이상하면 재부팅해서 새 드라이버를 적용한다.

6. **PyTorch 2.14.1**

   PyTorch(파이토치)는 파이썬으로 신경망을 만들고 학습시키는 라이브러리다. 층을 구성하고, 데이터를 넣고, 오차를 줄이는 연산이 들어 있다. 이미지 분류나 언어 모델에서 자주 사용한다.

   버전 2.14.1 뒤에 `+cu126`이 붙으면, CUDA 12.6 GPU용 빌드다. 함께 설치한 패키지는 아래와 같다.

   | 패키지 | 버전 | 하는 일 |
   |---|---|---|
   | torch | 2.14.1+cu126 | 신경망 계산 |
   | torchvision | 0.29.1+cu126 | 이미지 모델용 도구 |
   | torchaudio | 2.11.0+cu126 | 오디오 모델용 도구 |
   | numpy | 2.4.6 | 배열 연산 |

   `torchvision`과 `torchaudio`를 같이 설치한 이유는, 이미지와 오디오를 다루는 과제가 뒤에 이어지기 때문이다.

### 🦄 3.5. GPU 계산 확인

설치 완료 문구만으로는 부족하다. 가상환경에서 GPU가 실제로 계산하는지 확인해야 한다. 순서는 네 단계다.

1. 가상환경을 활성화한다. `conda activate dev`
2. 파이썬을 실행한다.
3. PyTorch를 불러온다.
4. GPU 사용 가능 여부와 GPU 이름을 출력한다.

```python
import torch
print(torch.__version__, torch.version.cuda, torch.cuda.is_available())
print(torch.cuda.get_device_name(0))
x = torch.randn(2048, 2048, device="cuda")
print((x @ x).sum().item())
```

### 🦄 3.6. 프로젝트 폴더와 원격 연결

```powershell
cd $env:USERPROFILE
cd Documents
mkdir aiprj
cd aiprj
claude --permission-mode dontAsk --dangerously-skip-permissions
```

- `cd`는 현재 폴더를 바꾼다. Change Directory의 약자다.
- PowerShell은 `cd`와 `Cd`를 같은 명령으로 처리한다. 특강 메모의 `Documnets`는 철자가 다르다. 실제 폴더 이름은 `Documents`다.
- `mkdir aiprj`는 `aiprj` 폴더를 만든다. 이미 있으면 그 줄은 건너뛰고 `cd aiprj`만 실행한다.
- 마지막 명령은 그 폴더에서 클로드 코드를 실행한다. 에이전트의 작업 디렉터리가 프로젝트 폴더가 된다.

클로드 코드가 실행된 **다음**에 입력하는 슬래시 명령은 Windows 명령이 아니다. `claude`는 프로그램을 실행하는 명령이고, `/`로 시작하는 입력은 실행 중인 세션의 명령이다.

```text
/remote-control aiprj
```

원격 제어(remote control)는 이 컴퓨터의 세션을 다른 클라이언트에서 이어서 조작하는 기능이다. `aiprj`는 그 세션 이름이다.

```text
/remote-control test
```

### 🦄 3.7. 하네스: 작업 기록 규칙

하네스(harness)는 여기서 **에이전트가 작업을 이어 갈 때 따르는 운영 규칙**을 뜻한다.

1. **HISTORY.md**

   한 일, 결과, 남은 문제를 시간순으로 적는다. 가장 최근 항목이 맨 위에 온다. 나중에 진행 위치를 이 파일로 확인하기 위해서다.

2. **STATS.md**

   버전, 경로, 용량, 확인 결과, 미완료 항목을 현재 값으로 덮어 쓴다. HISTORY.md가 지난 작업 기록이라면, 이 파일은 현재 상태다. 마지막 갱신 날짜를 같이 적는다.

3. **wiki**

   설치 방법, 버전을 고른 이유, 오류 해결 과정을 주제별 페이지로 남긴다. 대화 내용은 세션이 끝나면 다시 찾기 어렵다. 파일은 남는다. 원본 메모와 정리 페이지를 구분하고, 목록(`index`)과 변경 기록(`log`)을 같이 수정한다. 같은 주제의 페이지가 있으면 새로 만들지 않고 기존 페이지를 수정한다. 확인하지 않은 값은 적지 않고, 추정은 추정이라고 표시한다.

이 PC에서는 그 파일이 `C:\Users\403\dev-env`의 `HISTORY.md`, `STATS.md`, `wiki/`에 있다. 프로젝트 폴더 `Documents\aiprj`도 같은 형식의 기록을 둔다.

### 🦄 3.8. 모델 역할을 나누기

성능이 가장 높은 모델에 모든 작업을 맡기면, 단순한 작업에도 비용이 큰 모델을 쓰게 된다. 특강의 비용 절감 방법은 역할을 나누는 것이다.

| 역할 | 모델 | 맡기는 일 |
|---|---|---|
| 메인 에이전트 | Sonnet 5.5 | 전체 작업을 나누고 진행을 유지한다 |
| 서브 에이전트, 구현 | Haiku 5.5 또는 Sonnet 5.5 | 일반적인 개발, 검색, 조사 |
| 서브 에이전트, 검토 | Opus 5.5 또는 Fable 5.1 | 리뷰, 검증, 중요한 설계 결정 |

메인 에이전트가 전체 작업을 보고, 조사는 더 작은 모델에, 마지막 검토는 검토용 모델에 맡기는 구조다.

병렬 진행은 여러 작업을 동시에 실행하는 것이다. 같은 파일을 동시에 수정하면 변경이 충돌한다. **서로 겹치지 않는 작업**만 동시에 진행한다. 조사와 다른 모듈 구현을 따로 진행하는 식이다.

워크플로는 그 역할의 순서와 담당을 정하는 것이다. 모델, API, 화면, 검토를 나누면 한 단계가 모두 끝난 뒤에야 다음 단계가 시작하는 대기 시간이 줄어든다. 특강의 문장은 "워크플로로 팀을 적절히 구성해서 최대한 병렬로 진행한다"였다.

### 🦄 3.9. 간단한 과제: 다섯 모델을 한 웹사이트로 연결

환경과 기록 규칙을 준비한 뒤 진행한 프로젝트다. 순서는 **작업 기록과 역할 규칙을 먼저 정하고, 그다음 모델을 설치한다.** 모델은 크기가 작은 것 다섯 개다.

<img src="/images/blog/ai/14/images1.webp"/>
<img src="/images/blog/ai/14/images2.webp"/>
<img src="/images/blog/ai/14/images3.webp"/>

1. **이미지 분류**

   사진 전체의 범주를 출력한다. 예: "이 사진은 고양이다."

2. **객체 인식**

   사진 안에서 사물의 위치까지 찾는다. 고양이와 공이 있으면 각각 경계 상자로 표시한다. 분류는 종류를, 객체 인식은 위치까지 다룬다.

3. **포즈 추정 (Pose estimation)**

   팔꿈치, 무릎, 어깨 같은 관절 위치를 점과 선으로 표시한다.

4. **얼굴 인식**

   사진에서 얼굴을 찾고, 누구의 얼굴인지 구분한다. 신원 정보가 포함되므로 사용할 사진과 범위를 제한한다.

5. **한국어 감정 분류**

   문장을 감정 범주로 분류한다. "오늘 너무 신나!"는 기쁨, "정말 속상해"는 슬픔이다.

각 모델은 **FastAPI**로 API를 제공한다. 화면은 분석 요청을 해당 주소로 보내고, API는 결과를 반환한다. 모델마다 API를 두면 화면은 모델 코드를 직접 호출하지 않는다.

화면은 **FastAPI의 Jinja2 템플릿**으로 만든다. Jinja2는 HTML에 값을 넣어 페이지를 만드는 템플릿이다. 제목, 버튼, 결과 영역은 미리 두고, 모델이 반환한 문장과 이미지를 그 위치에 출력한다. 다섯 API를 하나의 웹사이트에서 호출하는 것이 과제다.

웹용 패키지는 `dev` 환경과 분리해서 **가상환경을 새로 만들고** 설치한다. 딥러닝 패키지와 웹 패키지가 같은 환경에 있으면, 한쪽 버전을 바꿀 때 다른 쪽도 영향을 받는다.

확인은 프로세스가 오류 없이 종료됐는지만 보지 않는다. **브라우저에서 사진이나 문장을 입력하고, 화면에 결과가 나오는지**까지 본다.
