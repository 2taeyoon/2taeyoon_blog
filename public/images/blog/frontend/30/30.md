블로그를 리뉴얼하면서 스터디 상세 페이지의 Markdown 본문과 목차(TOC)를 다시 짰습니다. 글이 길어질수록 목차와 본문의 동기화가 UX를 좌우한다는 걸 체감했습니다. `StudyMarkdown.tsx`와 `StudyToc.tsx` 안에 흩어져 있던 heading id 규칙과 스크롤 기반 활성 표시(`is_active`)를 에이전트와 함께 정리했고, 여기서는 나중에 다시 읽어도 맥락이 잡히도록 스스로에게 설명하듯 남겨 둡니다. 아래 코드는 모두 `src/features/study-detail` 기준입니다.

## 🦮 블로그 리뉴얼: Markdown 본문과 목차

처음 구조에서는 TOC에서 쓰는 anchor 문자열과, 실제 HTML로 렌더된 제목의 `id`가 서로 다른 규칙을 타거나 한쪽만 수정되는 일이 생기기 쉬웠습니다. id 규칙이 바뀔 때마다 두 컴포넌트를 동시에 손봐야 한다는 건 버그의 전형적인 온상입니다. 그래서 “id는 한 규칙으로만 정의하고, TOC와 스크롤 추적은 그 규칙을 소비만 한다”는 방향으로 역할을 쪼갰습니다.

- `rehypeHeadingAnchor.ts`: Markdown → HTML 변환 과정에서 `h2`/`h3`에 `id`를 주입
- `headingAnchor.ts`: TOC 쪽에서 동일 규칙으로 anchor id 계산 (`rehype`가 여기 함수를 import)
- `useActiveTocAnchor.ts`: 스크롤 위치를 보고 현재 읽는 섹션에 맞는 항목만 활성화

공통 규칙의 단일 출처는 `headingAnchor.ts`입니다.

```typescript
// headingAnchor.ts
export const HEADING_ANCHOR_PREFIX = "section";

type HeadingLevelItem = {
  level: 2 | 3;
};

export const getH2AnchorId = (h2Index: number) => `${HEADING_ANCHOR_PREFIX}-${h2Index}`;

export const getH3AnchorId = (h2Index: number, h3Index: number) =>
  `${HEADING_ANCHOR_PREFIX}-${h2Index}-${h3Index}`;

export const createTocAnchorItems = <T extends HeadingLevelItem>(items: T[]) => {
  let h2Index = 0;
  let h3Index = 0;

  return items.map((item) => {
    if (item.level === 2) {
      h2Index += 1;
      h3Index = 0;
      return { ...item, anchorId: getH2AnchorId(h2Index) };
    }

    if (h2Index === 0) h2Index = 1;
    h3Index += 1;
    return { ...item, anchorId: getH3AnchorId(h2Index, h3Index) };
  });
};
```

## 🦮 본문 쪽: rehype에서 id를 고정한다

블로그 본문은 클라이언트에서 DOM을 만든 뒤 뒤늦게 id를 붙이기보다, 렌더링 파이프라인 안에서 id가 확정되는 편이 안전합니다. `StudyMarkdown`에서 `rehypeHeadingAnchor`를 플러그인으로 넣고, 트리를 순회하며 `h2`/`h3`에 위와 같은 id를 붙입니다.

```typescript
// rehypeHeadingAnchor.ts
import { getH2AnchorId, getH3AnchorId } from "./headingAnchor";

type HastNode = {
  type?: string;
  tagName?: string;
  properties?: Record<string, unknown>;
  children?: HastNode[];
};

export const rehypeHeadingAnchor = () => {
  return (tree: HastNode) => {
    let h2Index = 0;
    let h3Index = 0;

    const visit = (node: HastNode) => {
      if (node.type === "element") {
        if (node.tagName === "h2") {
          h2Index += 1;
          h3Index = 0;
          node.properties = { ...(node.properties ?? {}), id: getH2AnchorId(h2Index) };
        } else if (node.tagName === "h3") {
          if (h2Index === 0) h2Index = 1;
          h3Index += 1;
          node.properties = { ...(node.properties ?? {}), id: getH3AnchorId(h2Index, h3Index) };
        }
      }

      if (!node.children?.length) return;
      for (const child of node.children) visit(child);
    };

    visit(tree);
  };
};
```

`ReactMarkdown` 쪽에서는 `remark`/`rehype` 배열에 끼워 넣기만 하면 됩니다. 본문이 부모 state 변경으로 불필요하게 다시 그려지지 않도록 `memo`로 감쌌습니다.

```typescript
// StudyMarkdown.tsx (요약)
import React, { memo } from "react";
import ReactMarkdown from "react-markdown";
import rehypeHighlight from "rehype-highlight";
import rehypeRaw from "rehype-raw";
import remarkGfm from "remark-gfm";
import { rehypeHeadingAnchor } from "./rehypeHeadingAnchor";

const remarkPlugins = [remarkGfm];
const rehypePlugins = [rehypeRaw, rehypeHeadingAnchor, rehypeHighlight];

function StudyMarkdownInner({ markdown }: { markdown: string }) {
  return (
    <ReactMarkdown remarkPlugins={remarkPlugins} rehypePlugins={rehypePlugins}>
      {markdown}
    </ReactMarkdown>
  );
}

export const StudyMarkdown = memo(StudyMarkdownInner);
```

클라이언트에서만 id를 붙이면 하이드레이션 직후·첫 페인트 전에 링크가 잠깐 어긋날 수 있고, 공유된 URL로 들어왔을 때 브라우저 기본 스크롤과도 타이밍이 어긋날 여지가 있습니다. 서버나 빌드 시점에 이미 `id`가 박혀 있으면 디버깅할 때도 “소스에 찍힌 HTML”과 TOC가 같은지 한눈에 비교하기 좋습니다.

## 🦮 TOC 쪽: 보여주기와 링크 생성만 남긴다

목차 항목의 `level`과 텍스트는 `useStudyDetail`에서 Markdown 줄 단위로 `##` / `###`를 파싱하거나, 렌더 후 `.blog h2, h3` DOM에서 모읍니다. TOC 컴포넌트는 그 배열을 받아 `createTocAnchorItems`로 `anchorId`만 붙이고, `href`와 `is_active`에 씁니다.

```typescript
// useStudyDetail.ts — 목차 후보 추출 (발췌)
export interface TocItem {
  id: string;
  text: string;
  level: 2 | 3;
}

const extractTocFromMarkdown = (markdown: string): TocItem[] => {
  if (!markdown.trim()) return [];

  const items: TocItem[] = [];
  const pushItem = (rawText: string, level: 2 | 3) => {
    const text = rawText.replace(/<[^>]*>/g, "").trim();
    if (!text) return;
    items.push({ id: `toc-${items.length}`, text, level });
  };

  const lines = markdown.split("\n");
  for (const line of lines) {
    const h3Match = line.match(/^###\s+(.+)$/);
    const h2Match = line.match(/^##\s+(.+)$/);
    if (h2Match) pushItem(h2Match[1], 2);
    if (h3Match) pushItem(h3Match[1], 3);
  }

  return items;
};
```

`StudyToc`에서는 `useMemo(() => createTocAnchorItems(items), [items])`로 anchor를 고정하고, 스크롤 고정(`fix`)용 `useEffect`는 같은 파일에 따로 둡니다.

```typescript
// StudyToc.tsx (앵커·활성 표시 핵심)
const tocItemsWithAnchor = useMemo(() => createTocAnchorItems(items), [items]);
const activeAnchorId = useActiveTocAnchor(tocItemsWithAnchor);

// ...

{tocItemsWithAnchor.map((item) => (
  <li
    key={item.id}
    className={`study_toc_item level-${item.level} ${activeAnchorId === item.anchorId ? "is_active" : ""}`}
  >
    <a href={`#${item.anchorId}`} className="study_toc_line">
      {item.text}
    </a>
  </li>
))}
```

Markdown에서 파싱한 목차 트리와 rehype가 실제로 부여한 id가 어긋나면 “클릭은 되는데 강조만 틀리다” 같은 증상이 나오기 쉽습니다. 그래서 TOC용 함수는 rehype 쪽과 같은 인덱스 규칙을 그대로 따르도록 맞춰 두는 것이 핵심입니다. 제목 텍스트를 slug로 바꾸는 방식은 충돌·특수문자 처리 때문에 예외가 많아지는 편이라, 이번에는 위치 기반 id로 단순화했습니다.

## 🦮 스크롤과 `is_active`: 훅으로 모은다

목차 UX에서 중요한 건 “지금 화면에 보이는 본문 구역”과 목차의 강조가 맞는 것입니다. `offsetTop`(기본 120)보다 위로 올라간 heading 중 가장 아래쪽을 현재 섹션으로 보고, 그 `anchorId`만 골라 냅니다.

```typescript
// useActiveTocAnchor.ts
import { useEffect, useState } from "react";

type AnchorItem = {
  anchorId: string;
};

export const useActiveTocAnchor = (items: AnchorItem[], offsetTop = 120) => {
  const [activeAnchorId, setActiveAnchorId] = useState<string | null>(null);

  useEffect(() => {
    if (!items.length) {
      setActiveAnchorId(null);
      return;
    }

    const update = () => {
      let currentActiveId: string | null = null;

      for (const item of items) {
        const heading = document.getElementById(item.anchorId);
        if (!heading) continue;

        if (heading.getBoundingClientRect().top <= offsetTop) {
          currentActiveId = item.anchorId;
        } else {
          break;
        }
      }

      setActiveAnchorId((prev) => (prev === currentActiveId ? prev : currentActiveId));
    };

    update();
    window.addEventListener("scroll", update, { passive: true });
    window.addEventListener("resize", update);

    return () => {
      window.removeEventListener("scroll", update);
      window.removeEventListener("resize", update);
    };
  }, [items, offsetTop]);

  return activeAnchorId;
};
```

`IntersectionObserver`로도 비슷한 UX를 만들 수 있지만, 이번에는 스크롤·리사이즈 기준으로 구현했고 필요 시 임계값이나 헤더 고정 높이만 조정하면 됩니다. 활성 id가 바뀔 때마다 전체 목차를 다시 그리지 않도록, 스타일만 토글하는 쪽에 가깝게 두는 것도 이후 성능 튜닝 여지로 남겨 두었습니다.

## 🦮 정리하면 기억할 네 가지

1. id 생성 규칙은 HTML이 나오기 전 파이프라인에서 먼저 고정한다.  
2. TOC는 같은 규칙을 가져다 쓰기만 하고, 중복으로 또 계산하지 않는다.  
3. 활성 목차는 별도 훅으로 두어 이벤트·계산을 한곳에 모은다.  
4. 그 결과 앵커 이동, 현재 섹션 표시, 규칙 변경 시 수정 포인트 최소화를 같이 달성한다.
